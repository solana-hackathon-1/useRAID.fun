# Wallet links example host

B1 also demonstrates the public internal resolver and storage revoke commands. The fixture host supplies trusted synthetic session/actor/clock/network observations and resolves inside the same transaction; it never treats a resolver result as proof or a public session token. After revoke the link stays permanently reserved, repeated revoke is a no-op, and primary payouts remain unchanged. This example has no auth session store or durable revoke audit; production session invalidation and acknowledgement belong to the separately reviewed B2 composing host. The shared challenge vocabulary is copied with the other canonical symlinks by `cp -RL`.

Minimal consuming host for the T006 wallet-link storage (additional verified wallets on one canonical HUMAN participant). Full module documentation, contracts, configuration names, lock order, retry rules and the step-by-step standalone run are in [docs/raid-wallet-links.md](../../docs/raid-wallet-links.md).

This directory declares its own dependencies (`package.json`), a minimal `User`/`WalletIdentity`/`Participant`/`WalletLink` schema and its own four migrations (host-owned `User` and `WalletIdentity` tables, plus the exact participant-mapping and wallet-link migrations as symlinks to the canonical SQL). `contracts`, `identity`, `identity-storage`, `identity-link`, `lib/identity-storage-adapter.ts`, `lib/wallet-link-proof.ts`, `lib/wallet-challenge-contract.ts` and its `lib/errors.ts` dependency are symlinks to the canonical sources; copy with `cp -RL` so the copy is self-contained. Supply `DATABASE_URL` for a disposable local database yourself; the host refuses non-local URLs and `NODE_ENV=production`. It never imports RAID configuration or `src/lib/db`.

PR-B1 also consumes `lookupWalletLink` on the real transaction port and an alternate deterministic port. The example verifies an ACTIVE credential resolves to its existing account and a revoked credential stays reserved; lookup is not signature verification or an authenticated session. The host owns those boundaries.

The host selects its SIWS network through `USDC_NETWORK=devnet` or `USDC_NETWORK=mainnet` (unset nonproduction defaults to mainnet). Its synthetic challenge nonce uses hex. The copied-helper consuming test in `tests/identity-link-boundary.test.ts` verifies devnet/mainnet and fail-closed production configuration without a database; the full database host execution is separate evidence.

The copied `lib/wallet-challenge-contract.ts` also exports the pure `walletChallengeMatchesOrigin(message, appUrl)` helper. Inject your host's current configured application URL; require both signed host and URI origin before consuming a challenge. Domain/port/scheme changes require a fresh signature, while path-only changes preserve a pending proof. This helper needs no RAID database/configuration and does not replace signature, expiry, purpose, digest or atomic one-use checks. `tests/identity-link-boundary.test.ts` exercises this copied consumer with explicit runtime wiring; the recorded standalone exact-dependency consumer check remains separate.
