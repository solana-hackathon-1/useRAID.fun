## Stable contract

Import `publishPracticeTrialDefinition`, `readPracticeTrialDefinition`, schemas, types and `PracticeTrialStorageError` from `src/skills/practice-trial-storage.ts`. The portable module imports only owned shared contracts, receipts, taxonomy authorization and Zod; no Next, Prisma, Root database/environment or provider dependency.

Publish `{actor, input, idempotencyKey, requestId}` with server-derived actor `{accountId, sessionHash}`. Strict input is `{trialId, expectedRevision, taxonomyReference, availability, draft}`. Draft reuses the complete [practice definition](raid-practice-trials.md), excluding only server-owned reference, publication time and state. It retains safe public/synthetic unpaid purpose, skill/domain, intended rank, variant, inputs, tools/AI policy, time, rubric/criteria, evaluation method, qualitative pass policy, attempt limits and accommodations. Client-supplied author/time/approval/assessment fields are rejected. PostgreSQL NUL/lone surrogate strings are rejected before any query. Revision storage uses positive INTEGER; expected revision is 0–2,147,483,646. Shared receipt normalized requests retain the 65,536 serialized-character bound.

Publish returns `{status: EXECUTED | REPLAYED, trial}`. Frozen stored DTO is `{version:'v1', definition, availability, taxonomyReference, publishedByAccountId, persisted:true, verifiesSkill:false, createsPermissionGrant:false, consumesCapacity:false, createsFinancialObligation:false}`. Definition uses unchanged pure v1 `state:PUBLISHED` and server database millisecond UTC time. Availability `AVAILABLE | RETIRED` belongs to each stored revision. A historical reference identifies a specific definition, availability, rubric and catalog snapshot; retirement never erases approval history.

Read `(tx, actor, trialId, revision?)` returns the actual saved DTO or null, requiring a current unrestricted own wallet/X session. Without revision it returns the immutable version selected by the current pointer; a concurrent later publication may follow it. Reads do not supply publisher authority or atomically admit/start an attempt. Future attempt commands must authorize and check current availability under their own transaction.

## Versions, concurrency and privacy

Lock order is receipt → User NO KEY UPDATE → Session SHARE → taxonomy advisory namespace12012/current SHARE → trial advisory12013/current UPDATE → rubric advisory12014. Bootstrap is serialized even without current rows. Hash collisions only serialize unrelated IDs. Recheck current authority after each wait. Host retries the entire transaction with original command identity on classified retry errors; unknown success is recovered using the original key/body, never a fresh key.

New publication binds the actual current saved taxonomy revision and exact stable skill/domain. New AVAILABLE requires an active skill. First trial revision must be AVAILABLE; later retirement is possible after skill retirement while referring to the actual current taxonomy. Trial family cannot change skill, domain or taxonomy ID; revisions are contiguous. Rubric `(recordId,revision)` identifies one immutable normalized criteria body globally, including across trial families. Reusing it with different criteria is `RUBRIC_CONFLICT`; new rubric versions must start at1 and remain contiguous. Changed content needs a new authorized version. Two publishers with the same expected trial revision have one winner; exact duplicate commands return one original result.

Successful version, global rubric introduction, current projection, finalized `PublishPracticeTrial` receipt and identifier-only private `skill.practice_trial_published.v1` audit commit atomically. Payload contains only `practiceTrialVersionId`; no definition, evidence, answers, criteria or assessed rank. No public outbox is permitted. Later retirement, publication or disabled writes does not change an authorized original receipt result. Removed current publication authority denies replay as well as new writes. Key reuse with a different normalized body fails after current authorization.

Migration28 `202610150001_practice_trial_definitions` adds `PracticeTrial`, `PracticeTrialVersion` and `SkillRubricVersion`; Prisma mirrors explicit composite relations. SQL validates strict complete JSON, UTF-16 text bounds/trim, exact column/reference/time bindings, immutable contiguous history, actual taxonomy/rubric snapshots, stable family, introduced rubric/version linkage and final matching admin receipt/audit/projection without outbox. Deferred constraints allow atomic cyclic introduction; all failures roll back. Privileged SQL remains privileged: actual cookie/session/allowlist policy is enforced by the locked module/host, not inferred from an audit row or database role label.
