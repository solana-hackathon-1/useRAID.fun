## HTTP interface and private DTOs

POST /api/v1/guild-drafts accepts application/json, Idempotency-Key and `{guildDraftId:null|uuid,expectedRevision,profile:{name,slug,description}}`. Creation uses null/revision0; updates use the current draft UUID/revision. Actor, session, verification, roles and private settings are forbidden input. It returns the storage's strict `{status:EXECUTED|REPLAYED,draft}` DTO. Save results must match the command's normalized profile, next revision and existing target ID; a corrupt/mismatched host result fails closed without serializing it.

GET /api/v1/guild-drafts/{uuid} authenticates before validating/reading the UUID and returns strict `{version:v1,draft,writesAvailable,unavailableReason:null|DISABLED}`. The returned draft ID must match the requested resource (UUID case is equivalent). Unknown and foreign drafts both yield the same NOT_FOUND envelope. Current cookie-derived account/session is reauthorized by storage; knowing a UUID or holding a project token grants no access. Both successful and failed replies carry Cache-Control private, no-store and Vary Cookie. No public route, cache, owner ID, cookie hash or private configuration is serialized.

Shared error envelopes include DRAFT_SLUG_UNAVAILABLE409 for a taken draft URL, REVISION_CHANGED409, IDEMPOTENCY_KEY_REUSED409, INVALID_COMMAND422 for immutable-slug/invalidinput, authentication401, forbidden/restriction403, missing404, rate429 and service503. Media415, oversized413 and stalled408 retain INVALID_COMMAND with the corresponding transport status. Messages/request IDs are fixed and sanitized; unknown errors are neither logged with private detail nor reflected. A lost acknowledgment retries the same key/body; do not create a new request identity for an unknown result. The draft namespace does not attest an external project's name or ownership.

## Root Next host and replaceable module

`createGuildDraftHandlers(GuildDraftHttpHost)` is a framework-free Request/Response factory in src/guild-profiles/http.ts. Host versionv1 injects current actor, origin check, rate limiter, own read/save and request-ID generator. Host auth/origin/rate denial uses GuildDraftHttpError401/403/429; domain/receipt errors retain their sanitized mappings. Strict DTO schemas reject extra private fields, inconsistent write configuration and target/snapshot substitution. A caller cannot supply a returned decision/DTO as authority.

The root Next adapter resolves requireUser and the actual server session cookie, hashes it, uses shared checkOrigin and the database limiter `guild-draft:{accountId}` at30commands/60seconds. GET never accepts a client actor. PostgreSQL transaction/locks/expiry/restriction/idempotency/provenance remain owned by the storage module and declared [consuming host](../examples/guild-drafts/README.md). No Next/Prisma/auth globals enter the portable HTTP factory. Internal host configuration requires exact GUILD_DRAFTS_ENABLED=true and non-demo mode for new writes; default false. Disabling new writes still delegates original receipt replay and own reads to storage, rather than rejecting them before reconciliation. No provider/financial/link/fold gate changes.

The shared src/http-contracts/json.ts reader retains the orientation transport's16384byte/5000millisecond bounds, content-type checks, fatal UTF8/JSON decoding and owned-reader finally cleanup. It checks actual streamed bytes even when Content-Length is absent or false, clears timers, cancels/releases only its own reader, and introduces no network/provider dependency. Both transports validate their own strict domain schema after the shared reader. Existing orientation assertions/timeouts are preserved.
