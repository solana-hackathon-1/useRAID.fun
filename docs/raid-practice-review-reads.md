# Protected private practice reviewer reads

T013D2/AG05/M1 supplies an actual PostgreSQL reader for a private practice submission and its original accepted full definition/rubric. It consumes the explicit finite assignment/current-use contract from raid-practice-review-assignments.md. R06/R11/R12/R15/R16, I05/I10/I13, D07/D08/D13 and AC73–75 apply. The reader does not confirm ownership, assess skill, create permission, consume work capacity or affect money. No HTTP endpoint/UI, provider, runner or real reviewer appointment is supplied; Root reads default off.

The stable entry is src/skills/practice-review-read-storage.ts: ReadPracticeReviewInputSchema, PracticeReviewReadRecordSchema, corresponding types, PracticeReviewReadError and readPracticeTrialForReview. Input is strict `{version:'v1',assignmentId:UUID,submissionId:UUID,purpose:'OWNERSHIP_REVIEW'|'ASSESSMENT_REVIEW'}` plus an actual `{accountId,sessionHash}` actor and required synchronous current canRead scope policy. The returned private DTO also includes accessId, an opaque server-generated audit correlation ID. Client roles, participant IDs, ownership or approval flags are rejected. The host provides the existing guarded READ_COMMITTED SQL transaction/whole retries/bounded driver, prior31DDL and actual identity/submission/definition/assignment/revocation state, current approved scoped read policy and DB clock. There is no new migration/model/Root package dependency or integration SDK/environment access inside the module. The host must permit the existing private command-receipt/audit tables to record authorized access; a read-only database role is insufficient.

Current exact evaluator identity, unrestricted own wallet/X session, actual exact assignment/submission/purpose, finite unexpired duration, no revocation and strict true read policy are checked before any private answer/explanation/disclosure columns are selected. Missing, foreign, wrong-purpose, expired, revoked and policy-denied resources return null. Invalid/expired/revoked sessions fail even for a missing object; admin role alone provides no use. Management authority and a saved appointment are distinct from current use. The callback receives current actual scope including subject/evaluator/issuing account, skill/domain, submission/purpose and saved expiry, as defined by D1. Missing policy fails closed, truthy nonboolean values deny, and thrown policy exceptions are sanitized.

The reader loads the saved submission joined to its actual immutable owned start and original definition version. The full strict definition and its canonical digest are checked; the saved strict submission schema preserves exact code whitespace, line endings, Unicode and claimant tools/AI declarations. Noncanonical normalized tool projections are rejected. The strict review DTO requires matching assignment/submission IDs, original definition/rubric IDs and revisions, and skill/domain. Its original full rubric/tool policy is suitable input for a later approved review; retirement of the current definition/catalog does not rewrite accepted evidence. Original claimant ownership is UNCONFIRMED, never an evaluation finding. Current ownership/evaluation decisions require a separate authorized immutable source.

After every private query the reader repeats held current identity/assignment/purpose/policy/expiry/revocation checks before returning. Actual session or assignment expiry during a query wait therefore yields an authentication error or null rather than returning a stale private body. No database row lock can freeze time. Keep the entire protected operation in the same held transaction; do not cache the result as permission for a later operation. The DTO marks private:true and isAuthorizationToken:false, includes the immutable historical appointment and submission plus original definition, and does not claim current authority beyond this read. Arbitrary source text/SQL/HTML is data: no execution, fetching, HTML rendering or provider access occurs here.

The host retains D1 sorted User/current Session and assignment mutex lock order. Reads take necessary locks and create no submission/ownership/assessment/permission/capacity/money mutation or public asset. Blueprint28.3 requires auditable private case access: after initial current authorization, each attempt generates an actual database UUID and records a ReadPracticeTrialForReview receipt plus skill.practice_review_access_authorized.v1 private audit before selecting body columns. Its payload is only practiceReviewAssignmentId, aggregate is the actual submission and actor is the current evaluator; the UUID is its correlation/accessId. There is no outbox. Callers cannot provide/reuse these audit keys. Separate read attempts get separate traces, including a retry after unknown response; no business operation is duplicated. The event records an authorized attempt, never proof of body delivery. Initial denials create no access record. Audit failure fails closed before private selection; authority is repeated after audit persistence (which may wait) and after private queries. A later policy/assignment denial can retain a previously authorized-attempt trace with no returned body. Exceptions roll back the same transaction. Deliver bytes only after the host has committed that transaction, as the Root and independent consumer do. Generic diagnostics should use request/opaque case identifiers and sanitized denial/error categories, never answer/explanation/disclosure/case reason/session bytes. The module returns INVALID_INPUT, AUTHENTICATION_REQUIRED, ACCOUNT_RESTRICTED, FORBIDDEN, RESOURCE_UNAVAILABLE, STORAGE_CONTRACT or STORAGE_UNAVAILABLE; shared receipt errors preserve whole-transaction retry behavior. Hosts own rollback and sanitization at connection/transaction boundaries and must not log raw driver data. No private content should be written to search, analytics, previews or public caches.

Root src/lib/practice-review-reads-host.ts composes runCommandTransaction with the actual actor/input and a current PRACTICE_REVIEW_READS_ENABLED===true callback. The flag defaults off and is read on each policy check. A final flag check also drops a module result if reads turned off before host return. Enabling this flag does not appoint a reviewer or bypass the actual saved scope/session checks. No Root flag is enabled in this change. Future HTTP composition must resolve the actor from current server auth, enforce its origin/rate/private-resource policy, use private/no-store responses and prevent public metadata/caching; this library alone is not a browser confidentiality audit or release gate.

The independently installed example examples/practice-review-reads declares actual minimal account/session/HUMAN/prior31 SQL and all pg/Zod/TypeScript/runtime dependencies. It creates synthetic saved consent/submissions/assignments, exercises exact private bytes/full rubric/current policy/zero private selection without assignment/revocation/private access audit/no business changes, and retains real transaction-local5s statement/2s lock/5s idle bounds. Copy it with canonical symlinks dereferenced and install its own package. The policy implementation may be replaced by another approved synchronous exact-scope projection while retaining all current checks and original history. There is no provider adapter to simulate.

Rollback disables new review reads, retains existing immutable history/receipts/assignments/revocations and continues current owner-only submission reads under their separate contract. No destructive database rollback/backfill is necessary. Revocation cannot recall disclosed material. Approved operating authority, O09 numeric calibration, O11 retention, real ownership/assessment/reassessment/fraud findings, committed eligibility projections, protected HTTP/screens and independent/UAT/business/release/full #55 acceptance remain separate obligations. Author tests and a staging merge do not establish those results.
