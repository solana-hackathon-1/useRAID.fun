# Safe lifecycle notifications and preferences

T042 tells the people involved in a Raid what changed, without ever putting the work's content in the message. A system dispatcher turns work events from the outbox into in-app notifications; a second pass reminds people of approaching deadlines. Messages are fixed text with an in-product path, never a title, scope, criterion, reviewer reason, artifact or link with a token. People can opt in to optional promotional notices; notices about their own work are not preferences. Only in-app notifications exist: no email, social or push provider is configured, and payment, dispute and access-readiness notices wait for those events to exist. All of it is behind default-off flags.

## Host contract

Flags are exact-string `true` and default off: `NOTIFICATIONS_READS_ENABLED` (page, list, mark read, preferences) and `NOTIFICATIONS_DISPATCH_ENABLED` (the worker's `notifications` step each minute: up to 100 outbox events and up to 100 reminders within 24 hours). HTTP (`/api/v1/notifications`, `private, no-store`): `GET` (own list, unread count, preferences), `POST {id}/read`, `POST preferences {promotional}`; origin, session and rate limit are checked before writes, queries and foreign methods are refused and every response is re-parsed. The page `/notifications` shows readable server-rendered state without scripts, marks as read and toggles the preference immediately, undoing it with a message if the server did not keep it.

## Data and database enforcement

Migration `202610260008_notifications` adds `Notification` (append-only apart from its first read, a closed list of kinds, the payload CHECK, a unique dedupe key, RESTRICT FK to `User`), `NotificationPreference` and `NotificationDispatch` (the processed marker). Backup and restore keep them with their events; destructive down migration is unsupported once used. Lock order for the member and reviewer reads is the existing current-Session proof only; the dispatcher takes no identity locks.

## Verification

`tests/notifications-db.test.ts` (real PostgreSQL: lifecycle recipients, repeated/racing/lost-marker jobs, late commit, privacy scan, deadline reminder windows, passed deadlines and amended versions, read/idempotency/isolation, preferences, append-only database guards), `-http` and `-host` unit tests (strict schemas, authority order, flags), and Playwright `playwright.notifications.config.ts` (synthetic PostgreSQL, desktop and mobile, development and production servers: safe notice, mark read across reload, preference choice, per-person isolation, signed-out and API access). All are mutation-checked; test names and genuine results belong in the PR. Limitations: no external delivery, no independent UAT, flags stay off in deployed environments.
