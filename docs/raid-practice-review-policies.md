# Actual versioned practice review policies

T013D3/AG05/M1 provides an actual immutable policy source for later ownership/assessment decisions. A caller-supplied policy-version label is not approval. A current scoped X administrator explicitly publishes private manual guidance for one actual saved original definition version and one purpose, OWNERSHIP_REVIEW or ASSESSMENT_REVIEW. R06/R11/R12/R15/R16, I05/I10/I13, D07/D08/D13 and AC73–75 apply. Publication is platform data approval, not staffed operating/legal/calibration/release sign-off. No real content, reviewer, numeric threshold, ownership, rank or permission is seeded; Root new publication and case-read use default closed.

The stable server entry src/skills/practice-review-policy-storage.ts exports PublishPracticeReviewPolicyInputSchema, UsePracticeReviewPolicyInputSchema, ObservePracticeReviewPolicyInputSchema, PracticeReviewPolicyRecordSchema/ViewSchema, corresponding DTOs, scope/options/command types, PracticeReviewPolicyError, publishPracticeReviewPolicy, readPracticeReviewPolicyAsAdmin, observeApprovedPracticeReviewPolicy and lockApprovedPracticeReviewPolicy. Imports are existing shared IDs/definition/purpose/current actor/assignment/command-receipt contracts and Zod; no Root auth/database global, environment variable, Next.js, external SDK or provider call enters the module.

The host owns one guarded PostgreSQL READ_COMMITTED transaction, actual current User/Session/Participant and prior32 SQL, current approved scoped synchronous publication/use predicates, DB clock, bounded driver/connection/transaction lifetime, rollback and whole-deadlock/serialization retries. Deliver private data only after COMMIT. Keep a lockApprovedPracticeReviewPolicy call in the same held transaction as the later decision; a separate Root snapshot is not commit authority. No policy callback may make slow external network/model/provider requests while locks are held. Such dependencies must be prepared before the transaction and resolved from current local approved state inside it.

Publish input is strict `{version:'v1',policyId,expectedRevision,definitionReference,purpose,state:'APPROVED'|'WITHDRAWN',guidance}`. Internal IDs and stored INTEGER revisions use existing contracts; guidance normalizes whitespace before its nonempty4000UTF16 technical bound and rejects NUL/lone surrogates before receipts/queries. These limits are not grading thresholds. The actual definition supplies immutable rubric/skill/domain/rank-target facts; policy contents cannot rewrite accepted definition/rubric/tool/pass rules. The first version must explicitly APPROVED. Withdrawal, correction and reapproval append the next contiguous version under CAS. Stable policy IDs cannot change original definition or purpose.

Exactly one canonical family exists for `(definitionVersionId,purpose)`, backed by SQL uniqueness, preventing callers selecting a weaker alternative family. Case lookup derives this scope from the actual saved submission/start, never a client definition label. A version's UUID is a durable future FK/source ID; its public reference is policyId/revision. Original approved data remains historical after withdrawal; original receipts/inspection do not imply current approval. Approved policy history also survives its issuer's later logout/role loss until explicit withdrawal/current use denial. A retired current catalog/definition does not rewrite accepted original evidence or prevent its authorized policy review.

Publication/replay/admin inspection require actual unrestricted User ADMIN, current own unexpired X Session and strict true canPublish of actual account/xId/policy/definition/rubric/skill/domain/targetRank/purpose. Root adds its dynamic actual X-admin allowlist. Relayed wallet proof/admin role alone is insufficient. Replay with new writes off returns the exact original immutable policy under current authority, with a fresh private-access trace; changed normalized body under the same key conflicts. Scoped admin inspection can read current or a specified historical version even with new publication off. Missing/denied scope yields no private guidance; ordinary users cannot inspect administration data.

An assigned evaluator first calls observeApprovedPracticeReviewPolicy with strict `{version:'v1',assignmentId,submissionId,purpose}`. It discovers the canonical current approved source without requiring a guessed version string. This is a private snapshot, never authorization for a later transaction. A later decision calls lockApprovedPracticeReviewPolicy with the same scope plus required nonnull expectedPolicyReference. Wrong expected current ID/revision is REVISION_CHANGED; missing/withdrawn source is null. Caller-selected other definitions/purposes/families cannot replace the actual accepted case. Current own unrestricted evaluator wallet/X session, real D1 assignment/exact scope/expiry/no revocation and strict true current canUse are all required. Admin role without the assignment gives no evaluator use. No data approval appoints a reviewer.

Policy use holds the canonical source mutex through the caller's later decision. It repeats actual case authority immediately after a policy-lock wait, before resolving/authorizing its source, after audit persistence and after private guidance. Session/assignment expiry or policy loss cannot return stale guidance. A new policy version/withdrawal waits for the held source transaction; stale expected references never silently adopt different rules. The record/view DTOs are readonly and isAuthorizationToken:false; record flags explicitly deny ownership/skill/permission/capacity/financial effects. APPROVED in a historical record is a publication fact, not a current effective grant or proof that O09/O11/release gates passed.

Blueprint28.3 privileged access is audited before private guidance selection. Publication emits skill.practice_review_policy_published.v1. Admin history/publish replies emit skill.practice_review_policy_access_authorized.v1; case use emits skill.practice_review_policy_use_authorized.v1. Each access attempt has a fresh database UUID/correlation accessId and private receipt, which callers cannot choose/replay as authority. Payloads contain only practiceReviewPolicyVersionId; no guidance/answer/session bytes or outbox. Audits represent authorized attempts, not proof of delivery. Initial denials do not record access. Audit failure blocks guidance; exceptions roll back the transaction. A later denial may retain an earlier authorized-attempt trace without returned content.

Actual Session and host configuration policy remain module/host checks; privileged DB ownership is not an authorization substitute.
