## Public interface and dependencies

Import `readPracticeTrial(context, policy)` or `preparePracticeTrialAttempt(context, input, policy)` from `skills/practice-trials`. Schemas/types and `PracticeTrialContractError` are in `skills/practice-trial-contracts`. `SkillVersionReferenceSchema` is additive in the existing skill contracts; canonical AccountId/ParticipantId/ParticipantSchema/SkillRankSchema and actual published-taxonomy schemas are reused. Existing eligibility v1, claim, Terms and HTTP shapes are unchanged.

Dependency direction: consuming host → practice module → Zod + skill/shared contracts. The host provides current time, actual immutable published taxonomy/definition, authenticated canonical HUMAN, fresh authoritative family-wide attempt history, selected approved accommodation and two synchronous local policy functions. No Next, Prisma, environment lookup, network, URL import, runner, logging or secret dependency exists. Transitive shared asset validation requires `bs58`. Node22.12+ and TypeScript5.9 are demonstrated by [the independently runnable console example](../examples/practice-trials/README.md).

`PracticeTrialPolicy` supplies `isApprovedDefinition(fullDefinition, now)` and `isApprovedAccommodation(fullAccommodation, now)`. Both must return the literal boolean true only for the entire normalized immutable payload currently approved by the host's actual authority. A matching reference, PUBLISHED/purpose tag, claimed admin role or client approval flag alone is insufficient. Resolve approved data before invoking the helper; verify public material ownership/sanitization, rubric correctness and operating authority there. Bind revocation and observation policy to current time. Ports cannot be supplied by an HTTP client. A real adapter must compare approved content and current authority; the example's byte and digest adapters are deterministic synthetic substitutes, not production approval.

Provider-backed approval must observe asynchronously outside this module, then supply a current local decision. Missing functions fail INVALID_HOST_CONTRACT; false/nonboolean approval denies; thrown exceptions become HOST_POLICY_UNAVAILABLE without private messages. Never substitute a success-shaped fallback on outage. No provider operation or in-flight side effect exists to drain in this slice. Future durable operations must remain pinned to their original definition/rubric/accommodation and authority when an adapter changes.

## Definition and data ownership

Strict v1 definitions contain a stable record ID + positive revision; publication date; stable skill/domain; target E–S rank; title/brief/variant ID; one or more PUBLIC/SYNTHETIC labeled text inputs; declared permitted tools, ALLOWED/PROHIBITED AI and assistance disclosure; expected time; exact rubric reference and unique criterion IDs/descriptions/required flags; MANUAL or AUTOMATED_WITH_MANUAL_REVIEW evaluator method; qualitative pass conditions; maximum attempts/cooldown and accommodation policy. All output objects, criteria, arrays and nested references are frozen. The skill must be active in the actual current taxonomy, in the exact domain, with no future publication.

No hidden answers, private annex, customer production purpose, evaluator private record or credentials belong in this public DTO. Extra fields fail strict parsing rather than being silently emitted. A schema cannot inspect whether a text is really public: full-payload host approval must enforce that provenance. Public disclosure returns only the definition; it does not expose account/history/accommodation context. This slice creates no public HTTP route or cache policy.

Bounds are technical validation limits, not chosen promotion/operating values: 200-character labels/tool names, 4000-character text, 50 inputs/tools/criteria, unique tools/criteria, maximum10000 attempts, maximum10080 expected minutes and maximum2147483647 cooldown seconds, integral finite values only. Time is UTC with at most millisecond precision. The actual approved definition chooses values inside those bounds; no default attempt count, cooldown, time, rank threshold, score conversion or rubric weighting is installed. OPEN O09 calibration and O11 retention remain unresolved. The sample's A target, 60 minutes, three attempts and 60-second cooldown are explicitly synthetic.

No `trial_definitions`, `trial_attempts` or `skill_assessments` tables exist yet. No migration/backfill occurs here. Stable IDs and immutable revisions are owned by the future approved-definition repository; retries cannot rewrite a published payload under its old revision. Retirement stops new preparation without deleting historical attempts/assessments. Existing durable taxonomy/claim tables and all27migrations remain unchanged.

## Private attempt preparation

Input is exactly `{version:'v1', definitionReference, accommodationReference:null|{recordId,revision}}`. The host context is separate and contains current actual actor/session/restrictions, canonical participant and current observations. It cannot be populated from client approval/count/rank/role fields. The authenticated account must own an unrestricted HUMAN mapping; wallet changes preserve the same canonical participant. No orientation history, token wealth, Guild relationship, earlier E-rank task count or prior purchased rank is required by this practice preparation.

Attempt history is CURRENT with participant ID, **stable trial ID across definition revisions**, observedAt/validUntil, attemptsUsed and lastAttemptAt, or STALE/UNAVAILABLE. The exact current canonical subject and trial family must match; freshness is observedAt ≤ now < validUntil. Zero attempts requires null lastAttemptAt and a positive count requires a nonfuture lastAttemptAt no later than the history observation. Old definition revisions must not reset the counter. Count exhaustion denies; cooldown denies until the exact configured time boundary. History outage/expiry is unavailable, never an invented zero. Separate endpoint rate limits and actual anti-replay/abuse policy remain host obligations.

The context's accommodation is the selected full current host-approved immutable grant or null. Consent names its exact reference. A grant binds this canonical participant and exact definition revision, current observedAt/validUntil and explicit effective maximumAttempts/expectedMinutes/cooldownSeconds. It changes neither rubric, tool rules, material, skill/domain nor target rank. Missing, altered, foreign, stale or unapproved grants deny. Its reference alone does not supply authority. No private reason/medical detail is accepted or emitted. Selection and approval workflow are future host work.

The frozen private result contains PREPARED, canonical participant ID, exact definition/rubric/taxonomy/accommodation references, skill/domain/target rank, variant, preparedAt, prospective attempt number and expectedMinutes. It has `persisted:false`, `verifiesSkill:false`, `isAuthorizationToken:false`, `createsPermissionGrant:false`, `consumesCapacity:false`, `createsFinancialObligation:false`. Target rank is the exercise's target, never an assessed rank. No private account/actor, brief/input bytes, history or receipt is emitted. Discarding or repeating preparation has no business effect.

## Permissions and state boundaries

| Actor / resource state                                         | Approved safe definition read             | Own attempt preparation                                           |
| -------------------------------------------------------------- | ----------------------------------------- | ----------------------------------------------------------------- |
| Visitor                                                        | Allowed after actual public-data approval | AUTHENTICATION_REQUIRED                                           |
| Own live unrestricted HUMAN                                    | Allowed                                   | Allowed only with exact current definition/consent/history/policy |
| Foreign canonical mapping                                      | Allowed safe public data                  | FORBIDDEN                                                         |
| Restricted account                                             | Allowed safe public data                  | ACCOUNT_RESTRICTED                                                |
| AI identity, token holder or Founder without own HUMAN context | No extra public rights needed             | No inherited preparation authority                                |
| Missing/retired/wrong-domain/unapproved definition             | Denied                                    | Denied                                                            |
| Stale counts or foreign/expired accommodation                  | Safe public read unaffected               | Denied                                                            |

Preparation is not the attempt-start linearization boundary. **The future durable host must atomically recheck actual session, current definition/approval/consent, restrictions, selected grant and family-wide history, then consume exactly one attempt and persist immutable attempt + original-result command receipt/audit.** Same actor/command/idempotency key with altered request must conflict; unknown saves require receipt reconciliation before another attempt. Two concurrent preparations can both return the same prospective number; this helper claims no DB race, durability, stored idempotency, timeout or cancellation verification. Reuse the same frozen definition/rubric/tool policy through submission and review rather than re-reading changed terms. A new version needs renewed consent.

Unpaid platform practice consumes no engagement capacity (blueprint13.1). Paid selection/customer work must use the actual funded engagement/capacity rules and cannot be represented by this contract. The module runs or fetches no submitted code/material. A future runner needs quarantine/isolation/tool enforcement, credentials separation, bounded execution and current provider approval. Similarity signals alone are not a fraud verdict. Authorized evaluator/attribution/reassessment/revocation/appeal commands remain separate; no preparation can manufacture a VERIFIED eligibility fact.

## Errors, verification and operations

Typed error codes are INVALID_INPUT, INVALID_HOST_CONTRACT, HOST_POLICY_UNAVAILABLE, AUTHENTICATION_REQUIRED, ACCOUNT_RESTRICTED, FORBIDDEN, RESOURCE_UNAVAILABLE, DEFINITION_UNAVAILABLE, SKILL_UNAVAILABLE, REVISION_CHANGED, ATTEMPT_HISTORY_UNAVAILABLE, ATTEMPT_LIMIT_REACHED, COOLDOWN_ACTIVE and ACCOMMODATION_UNAVAILABLE. Errors contain the category only. Log request/reference IDs and categories in the host, never full definitions, private history, exceptions or grants. After unavailable facts refresh actual host observations; after version changes obtain exact renewed consent; after limit/cooldown denial use approved policy, without resetting history. There is no background worker, secret/configuration name, network request or task-owned server to stop.

Behavior tests in `tests/practice-trials.test.ts` cover denied/allowed authority, altered immutable content, tool/material/rubric constraints, canonical binding, attempt count/freshness/cooldown, exact accommodation and no-effect/privacy boundaries. The boundary suite copies/runs the example with explicit CI runtime and alternate policy adapters; separate own-install evidence verifies its declared dependencies and strict types. Both are registered in E04/global inventory and ordinary Vitest discovery before CI artifacts. Full hosted exact-SHA jobs, independent criterion review, representative UAT and business/release approval remain separate NOT VERIFIED obligations. No browser-visible behavior is added, so a new Next development preview/browser suite is not required for this slice.
