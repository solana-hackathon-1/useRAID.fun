# Scoped private practice reviewer assignments

T013D1/AG05/M1 implements explicit immutable reviewer appointments and revocations for existing private submissions. R06/R11/R12/R15/R16, I05/I10/I13, D07/D08/D13 and AC73–75 apply. An appointment creates permission for exactly one saved submission, evaluator account, declared purpose and finite duration. It does not confirm ownership, skill, trust, eligibility or a work outcome. Current transaction-held use must still pass the host's approved exact-scope policy. No Root route/UI or protected answer reader is delivered here; no real appointment is seeded. New Root management writes default off.

`src/skills/practice-review-assignment-storage.ts` exports v1 schemas, records, typed sanitized errors, issuePracticeReviewAssignment, revokePracticeReviewAssignment and lockPracticeReviewAssignment. Import this entry directly. It depends only on Zod/shared contracts, command-receipt SQL port, existing locked skill actor and pure approved definition contracts. No Next.js, Prisma, provider SDK, credential, environment variable or external network call lives in the module.

The host provides one real PostgreSQL READ_COMMITTED transaction, current User/Session/Participant records and existing immutable submissions/starts/definitions, migration31 after the prior30, database clock, explicit synchronous current canManage/canUse policies, bounded connection/statement/lock/transaction settings, whole-transaction deadlock/serialization retries and rollback. The transaction stays open through the protected operation. Use the same original idempotency key/body after unknown success; never retry just the final SQL insert. External policy discovery happens before a transaction; its current local approved projection is checked within it.

Issue input is strict `{version:'v1',submissionId:UUID,evaluatorAccountId:InternalId,purpose:'OWNERSHIP_REVIEW'|'ASSESSMENT_REVIEW',expiresAt:UTC timestamp with at most millisecond precision,reason:normalized nonempty text≤2000 UTF16 units}`. Actor is actual `{accountId,sessionHash}`; client role/participant/approval flags are rejected. SQL generates immutable assignment ID/issuedAt. The target is an existing unrestricted account and the subject is the actual saved canonical HUMAN; direct self-review is denied. The evaluator need not already have a session when appointed. Current unrestricted X ADMIN, own unexpired X session and strict true canManage of actual subject/evaluator/submission/skill/domain/purpose/expiry are required for issue, revoke and original management replay. Management policy receives the acting administrator as issuerAccountId and current xId. It must enforce any additional conflicts/operating eligibility. Root's adapter adds its dynamic actual X-admin allowlist and exacttrue PRACTICE_REVIEW_ASSIGNMENTS_ENABLED flag; no flag is enabled in this change.

Revoke input is strict `{version:'v1',assignmentId:UUID,reason}`. The immutable revocation has a separate generated ID/database time/current administrator/receipt. New issue/revoke writes respect allowNewWrites; current original-result receipts remain available when off. Revocation of an expired assignment is allowed and historical issue replay remains ISSUED without claiming current permission. Another key for an already revoked assignment returns ALREADY_REVOKED. Renewing authority creates a new explicitly approved assignment with its own key. Multiple assignments may coexist; this does not select exclusivity, quorum, numeric calibration or case decision policy.

The current-use input is strict `{assignmentId,submissionId,purpose}` and a current actual evaluator actor. `lockPracticeReviewAssignment` returns the immutable appointment or null for missing/foreign/wrong-scope/expired/revoked/policy-denied assignments. The actor's current unrestricted own wallet/X session is required even for null lookups. Admin role alone provides no use. canUse receives actual immutable scope including historical issuing account, subject, evaluator, submission and skill/domain/purpose/expiry; no current issuer X-session/role is implied. An appointment remains effective after its issuing administrator's later role change unless revoked/expired/current use policy denies it. It is not a delegated admin role. Missing/nonfunction policies fail closed; thrown policy errors become sanitized STORAGE_UNAVAILABLE; nonboolean truthy values are denied. Its returned DTO has `isAuthorizationToken:false`; it cannot be cached or passed as authority for a later transaction. Call it again when needed and recheck current authority after any protected operation that may wait. It never selects an answer/explanation/disclosure or returns confirmed ownership/assessment.

Authentication preflight is nonlocking and precedes management target lookup to avoid unauthenticated target enumeration. All actual management authority is checked again under held locks. Receipt arbitration comes before sorted multi-user locks. Every involved User is acquired by stable account-ID order before current actor/Session checks; the evaluator and subject are distinct. Revoke/use then serialize on assignment advisory mutex namespace12017. Current Session validity and assignment DB-clock expiry are checked after waits; use checks expiry once more immediately before return. SQL guards also acquire sorted User rows, require actual distinct subject/evaluator and administrator, immutable finite normalized text/time/FK shape, receipt chronology and finalized matching private identifier audit. SQL constraints complement current app session/policy checks; privileged DB ownership does not replace authorization. No module operation calls a provider or executes submitted code while holding locks.

Errors are INVALID_INPUT, AUTHENTICATION_REQUIRED, ACCOUNT_RESTRICTED, FORBIDDEN, SELF_REVIEW_FORBIDDEN, RESOURCE_UNAVAILABLE, EXPIRY_INVALID, ALREADY_REVOKED, WRITES_DISABLED, STORAGE_CONTRACT and STORAGE_UNAVAILABLE; shared receipt errors preserve key conflicts/whole-transaction retries. No private body or raw database/policy exception is logged or embedded. Private audit events carry only practiceReviewAssignmentId or practiceReviewRevocationId, no answer/reason/session bytes and no outbox. Stored case reasons are private metadata. Operational monitoring should use request/receipt/opaque assignment references, expiry/revocation/denial/error categories and cleanup state.

The independently installed consuming example is `examples/practice-review-assignments`: actual minimal PG dependencies/current synthetic canonical workflow, real local bounds, exact scope/policy/current use/revocation/original replay. Dereference canonical symlinks to copy it; install its declared packages into its own node_modules. No hidden Root state or credentials are required. An approved alternate policy can replace local predicates while retaining exact-scope and current authority checks; provider capabilities are absent rather than simulated.

Rollback disables new management writes and retains immutable audit/receipt/appointment/revocation history and current checks. Never delete revocations or treat historical ISSUED DTOs as current permission. Expiry/revocation cannot recall previously disclosed material. O09 numeric scoring/calibration, O11 retention, approved staffed operating policy, private protected reads, actual ownership/assessment/reassessment/fraud findings, independent review/UAT/business/release acceptance remain separate dependencies. Full #55 stays open; local author tests are not independent acceptance.

## Administrator HTTP transport (T013 assignment-admin)

`src/skills/practice-review-assignment-http.ts` exports `createPracticeReviewAssignmentHandlers(host)` returning `issue(request)` and `revoke(request, params)`, the strict v1 result schemas and `PracticeReviewAssignmentHttpError`. It adds no authority: every decision is made by the storage commands above under their held locks. Routes: `POST /api/v1/admin/practice/review-assignments` and `POST /api/v1/admin/practice/review-assignments/{assignmentId}/revocations`; there is no GET/HEAD/PATCH/DELETE and no generic state setter. Root composes them in `src/lib/practice-review-assignment-http.ts`.

The host supplies `requestId`, `origin` (CSRF/allowed origin, run first), `actor` (an actual X-connected administrator with the live session hash), `rateLimit` (Root key `practice-review-assignments:<account>`, 30/60) and the committed `issue`/`revoke` commands (`practice-review-assignments-host`, which keeps `PRACTICE_REVIEW_ASSIGNMENTS_ENABLED` default off). Order is origin → actor → quota → no query string → `Idempotency-Key` → origin-first JSON bounded to 16 KiB → strict input → command → result binding. Unknown fields, wrong version, client-supplied issuer/state, path/body id mismatch and bad keys are 422 before any command; oversize is 413.

Responses are `private, no-store` with `Vary: Cookie` and a strict `{version,status:'EXECUTED'|'REPLAYED',writesAvailable,unavailableReason,assignment|revocation}` body bound to the request (echoed submission/evaluator/purpose/expiry/reason; issuer or revoker equals the actor). A malformed or mismatched host result is a 503, never a success. A write gate that closes after commit does not hide the committed result. Mapping: `INVALID_INPUT`/`EXPIRY_INVALID`→422, authentication→401, `ACCOUNT_RESTRICTED`/`FORBIDDEN`/`SELF_REVIEW_FORBIDDEN`→403, `RESOURCE_UNAVAILABLE`→404, `ALREADY_REVOKED` and key reuse→409, `WRITES_DISABLED`, storage and unknown faults→503, using only protocol messages (no ids, SQL or driver text). The same key and body replays the original result; the same key with another body is `IDEMPOTENCY_KEY_REUSED`.

The consuming example wraps the same commands in this transport with injected origin/actor/quota stubs and exercises issue, replay, key-reuse conflict and revoke against real PostgreSQL. A real deployment must replace those stubs with an authenticated administrator actor and an origin check. Disclosed material cannot be recalled by revocation. No real appointment, flag enablement, operating policy, management screen, independent review or UAT is provided by this transport.
