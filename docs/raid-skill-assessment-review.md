# Authorized private assessment preparation

T013B / issue55 owns `src/skills/assessment-review-contracts.ts` and `assessment-review.ts`. The module prepares reasoned manual review, capability reassessment and fraud-revocation **proposals** against actual authorized host facts. It implements a reusable foundation for blueprint07–09/13/25.3/26/28–29 under R05/R06/R12/P07/I06/I07/I10/I13/R15/R16 and AC06/73–75. Actual committed assessments, reviewer API/screens, calibrated numeric promotion and full T013 acceptance remain NOT VERIFIED.

## Interface and ownership

`prepareSkillAssessmentReview(context, input, policy)` returns a private PROPOSED decision. `prepareSkillAssessmentReassessment(context, input, policy)` returns a private PROPOSED capability/fraud action. Both parse strict v1 schemas, freeze their parsed private context/input and result, and throw `SkillAssessmentReviewContractError` categories. The schemas and `SkillAssessmentReviewPolicy` are exported from `assessment-review-contracts`. `SkillAssessmentSnapshotSchema` describes an **actual committed immutable private record** supplied by the host, not a candidate.

Dependency direction is consuming host → assessment module → Zod + canonical identity/rank/catalog/version-reference and PracticeTrialDefinition contracts. Existing eligibility v1, private claim, Terms and Root HTTP shapes remain unchanged. A future assessment projector must deliberately construct its authorized committed SkillEvidenceFact; neither the proposal nor its nested proposed assessment parses as that projection. No global environment, Next, Prisma, network, runner, logger or secret is imported. Transitive shared asset validation requires bs58. [The own-install console example](../examples/skill-assessments/README.md) declares Node22.12+, all pinned runtime/type dependencies and synthetic fixtures.

The host supplies actual current time/session/restrictions, canonical HUMAN subject, immutable published taxonomy, stable subject/skill assessment record ID, approved assessment policy version and fresh current assessment/absence observations. Review additionally supplies the original immutable approved practice definition and actual submitted evidence observation. Reassessment supplies a current scoped case with immutable evidence versions. No corresponding trial/attempt/assessment tables or approved Root evaluator/rubric registry exists yet; no schema/all27DDL/dependency migration is introduced here.

Assessment identity is global to canonical participant + stable skill, rather than copied by wallet or Guild. Actual stored revisions preserve rank, rubric/definition/submission/evidence, evaluator, issuance/validity, confidence statement and sample count. New publication/retirement retains existing identities and historical definitions. The helper can review actual submitted historical work after category retirement; a retired category still prevents starting a new practice trial through the separate preparation contract.

## Actual host authority

`SkillAssessmentReviewPolicy` declares three synchronous local operations:

- `isApprovedDefinition(fullDefinition, now)` compares the complete normalized immutable accepted definition/rubric/tool/variant/pass-policy payload with the host's actual approved record eligible for review. Reference or PUBLISHED/purpose flags alone prove nothing.
- `canPrepareReview(fullReadonlyContext, fullReadonlyInput)` checks the current evaluator's explicit permission for this canonical subject, skill, immutable submission/definition/rubric, assessment version, policy and proposed decision. It also enforces the approved qualitative pass conditions not reducible to the helper's minimum required-criterion checks, and any reinstatement/high-impact authority.
- `canPrepareReassessment(fullReadonlyContext, fullReadonlyInput)` checks separate current authority for the exact subject/current assessment/case/action/policy. Fraud revocation requires an actual reasoned reviewed fraud case; a reason tag, risk signal or reported similarity alone supplies no proof.

Every port must return the literal boolean true to permit the operation. Missing functions fail INVALID_HOST_CONTRACT, denial/nonboolean values fail FORBIDDEN or DEFINITION_UNAVAILABLE, and thrown private exceptions become HOST_POLICY_UNAVAILABLE without their messages. The helper checks current session, evaluator restriction, HUMAN mapping and self-review before invoking a port; scope denial precedes domain/version failure disclosure. Neither platform role, Guild Founder/holder status nor product AI implies evaluator authority. Ports come only from trusted composition; an HTTP client cannot provide one or populate host context.

Current provider-backed authority/evidence must be observed asynchronously outside the pure helper and pinned to current local facts. Outage is not an approval or an invented empty record. There is no external effect, provider wait, database lock or in-flight operation in this module. The console's byte/digest definition adapters and deterministic scoped grant demonstrate substitution, not real approval. A production host must supply real access-controlled data, precise authority revisions and current policy, and persist that provenance in its audit at the durable command boundary. No commercial evaluator/provider, retention policy or credentials are installed.

## Current records, absence and evidence

Current assessment observations bind canonical participant, stable skill, observedAt and validUntil, with an immutable record or explicit null. STALE/UNAVAILABLE are separate; null means actual current observed absence, never a client assertion. Freshness is observedAt ≤ now < validUntil. A record must match the host-owned stable record ID, participant, skill/domain and cannot have future issuance or reassessment preceding issuance. It can be VERIFIED, REASSESSMENT_REQUIRED or REVOKED, retaining its actual assessed rank. Input expectedAssessmentReference must exactly match current record/reference or actual observed absence; conflicts never erase old data. Revision overflow fails closed.

A review submission binds its exact version, canonical participant, original definition version, SUBMITTED state and actual submittedAt/observedAt/validUntil. Publication must precede submission; submission must precede its observation. Evidence references are immutable versions, nonempty and unique by stable record ID; mixing two versions of one current evidence record is rejected. The host reports actual CONFIRMED/UNCONFIRMED/DISPUTED ownership and sampleSize. A sample can be a reviewed case within one artifact; evidence-reference count is not treated as a sample count or confidence score. Providers/assets are never fetched by this module and a proof URL or social link alone cannot establish ownership.

A reassessment case binds the canonical participant and exact current assessment version, fresh observation interval and nonempty unique immutable case evidence. The actual evidence and process remain host authority, with case-specific access. Changing a wallet, a reliability incident, token balance, stale external token or missing provider response cannot automatically remove skill history or revoke verification.

Bounds are technical parser limits: 50 evidence/criterion entries, 2000-character normalized reason/confidence text, positive sample counts ≤1000000, canonical positive safe-integer revisions and UTC time with at most milliseconds. Actual approved rubrics/authorities choose their own policies. Numeric scoring/promotion/calibration (OPEN O09), retention (O11) and relevant operating/provider approvals remain unresolved. Qualitative confidence is the evaluator's explanation, not a probability or auto-converted rank.

## Manual review contract

Input contains v1, exact expected definition/rubric/submission/current assessment references, VERIFY/MORE_EVIDENCE/NOT_DEMONSTRATED, reason, confidence explanation, one reasoned MET/NOT_MET/UNCERTAIN finding per actual rubric criterion and an explicit optional future reassessment date. Strict parsing rejects extra actor, subject, role, approval, rank, score or wealth fields. There must be exactly one finding for every original rubric criterion, no extras/duplicates/empty reasons. The helper does not infer requirements from free text.

VERIFY requires confirmed ownership, every criterion declared required in the approved rubric to be MET, and actual host-approved decision/pass conditions. It proposes **only the original exercise's target rank for its exact skill/domain**, with no unrelated E-task history requirement. There is no score conversion, arbitrary promotion threshold or claim that one trial proves permanent/highest expertise. Stronger/multiple evidence and approved evaluator conditions remain actual rubric/policy responsibilities.

All result objects have state PROPOSED and persisted/verifiesSkill/isAuthorizationToken/createsPermissionGrant/consumesCapacity/createsFinancialObligation false. The parent identifies evaluator, subject, exact original references, previous assessment reference, criteria, private reason/confidence and preparedAt. VERIFY's nested `proposedAssessment` also has state PROPOSED, **proposedState** VERIFIED and **proposedRank**, not actual state VERIFIED or assessedRank. It contains the prospective stable record/revision, skill/domain, original definition/rubric/submission/evidence, approved policy/evaluator, proposed date, confidence/sample count and the same false-effect flags. It cannot become an eligibility fact by being passed to the existing strict projection schema.

MORE_EVIDENCE and NOT_DEMONSTRATED produce no nested assessment, preserving any existing rank/verification/history unchanged. A fresh authorized review can propose reinstatement after revoked evidence through new owned evidence and actual reinstatement authority; no field silently clears the earlier revocation. The future durable host must append history, never overwrite it with a claimant's level or an unsuccessful review.

## Capability reassessment and fraud revocation

Input binds the exact current assessment version and a reasoned action. REQUIRE_REASSESSMENT uses CAPABILITY_RECHECK with an explicit future dueAt. REVOKE uses only FRAUDULENT_ASSESSMENT_EVIDENCE; no reliability/wealth/similarity category can be substituted. Both need actual scoped current case authority and evidence. A missing record or revoked record cannot be revived by this command; state conflict denies it.

The private result remains PROPOSED. It names proposedState REASSESSMENT_REQUIRED/REVOKED, exact previous reference/rank, prospective next revision, current policy/evaluator and immutable case evidence. The capability action preserves its explicit dueAt; the fraud action has dueAt null. Neither changes actual current state, due date, old issuer/issuance/evidence, appeal rights, claims or access. A due date is an approved intended deadline, not a running worker or automatic revocation. Actual notice/case review/appeal/closure and timeout jobs remain future storage/operating work.

## Actor and state matrix

| Actor/resource state                                 | Manual proposal                                            | Reassessment/fraud proposal                       |
| ---------------------------------------------------- | ---------------------------------------------------------- | ------------------------------------------------- |
| Visitor/expired session                              | AUTHENTICATION_REQUIRED                                    | AUTHENTICATION_REQUIRED                           |
| Current scoped independent evaluator                 | Allowed only for exact approved submitted/current versions | Allowed only for exact current case/action        |
| Subject reviewing their own canonical account        | SELF_REVIEW_FORBIDDEN                                      | SELF_REVIEW_FORBIDDEN                             |
| Restricted evaluator, unscoped Founder/holder/AI     | Restricted/denied                                          | Restricted/denied                                 |
| Non-HUMAN canonical subject                          | RESOURCE_UNAVAILABLE in this v1 slice                      | RESOURCE_UNAVAILABLE                              |
| Changed original version/current assessment          | REVISION_CHANGED                                           | REVISION_CHANGED                                  |
| Unknown/expired assessment/submission/case           | Unavailable, preserving history                            | Unavailable, preserving history                   |
| Unconfirmed ownership or unmet required rubric       | VERIFY denied; reasoned incomplete result possible         | No fraud inference; separate actual case required |
| Retired stable skill with real historical submission | Review remains possible under actual authority             | Existing historical record remains addressable    |

A subject's independent restrictions, Guild Trust, holder relationships and payout claims are not modified. Global capability and resource permissions remain separate. These functions require no engagement capacity; a paid reviewer assignment must separately use funded work/one-active capacity contracts and cannot inherit an extra work slot from this helper.

## Durability, privacy and recovery obligations

This is preparation, not stored decision acceptance. The future durable host must atomically lock/recheck actual session/restriction, precise current evaluator scope/authority revision, original definition/rubric/submission/evidence and actual current assessment/absence, append an immutable private decision/history and audit, store an original-result idempotency receipt, then project **committed** authorized records. A same actor/command/key with altered payload must conflict; unknown saves require reconciliation before retry. Concurrent preparations may share the same prospective revision; this module proves no database race or durable idempotency. Do not use a candidate as a permission/admission token or bypass the invariant owner with direct table writes.

All review/case/reason/confidence/evaluator/subject data is private. No public DTO, route, HTML/metadata/hydration/search, log or notification payload is introduced. A future endpoint must authorize resource access before loading/displaying these facts, enforce session/origin/rate/body limits and private no-store cache policy, and construct any public profile projection deliberately. Do not log full context/input/result or private exceptions. The module outputs no submission body/answer/code and executes no uploaded code, model prompt or URL; quarantined evidence and real sandbox/tool/provider approval remain host/runner requirements.

Typed errors are INVALID_INPUT, INVALID_HOST_CONTRACT, HOST_POLICY_UNAVAILABLE, AUTHENTICATION_REQUIRED, ACCOUNT_RESTRICTED, SELF_REVIEW_FORBIDDEN, FORBIDDEN, RESOURCE_UNAVAILABLE, DEFINITION_UNAVAILABLE, ASSESSMENT_UNAVAILABLE, SUBMISSION_UNAVAILABLE, CASE_EVIDENCE_UNAVAILABLE, REVISION_CHANGED, REVISION_EXHAUSTED, EVIDENCE_NOT_CONFIRMED, RUBRIC_NOT_MET and STATE_CONFLICT. On unknown facts refresh current observations; on changed versions reload the exact original accepted versions/current record; on scope denial obtain actual assignment authority. Never convert unavailable evidence to a fabricated denial/revocation/verification.
