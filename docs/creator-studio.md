# Creator Studio v1

X Campaign and Existing Token use one campaign engine. Launch Token remains Coming soon. Verified X users can save and launch without legacy creator approval; suspensions and global campaign limits still apply.

## Local walkthrough

Run `docker compose up -d db`, then `npm run studio:preview`. Open http://localhost:3007/studio-test and enter test Studio. It supplies a fixture X identity, verified test wallet, and 1,000 test USDC. Create Raid → X Campaign → name → any valid public X status URL → Preview → target/budget → duration → accept test terms → Fund & Launch. Manage page lets you simulate a contributor, reach target, and fast-forward test review. Operations confirms test reward receipts. Balance supports test deposits and withdrawal requests.

Sandbox cannot run in production: requires development runtime, explicit flag, localhost canonical URL, and database named `useraid_studio_test`. Preview binds loopback. Separate `.next-studio` output, session cookie, and database avoid production data and server conflicts. All fake financial entries use sandbox network. No real X calls, signatures, or transfers occur. Fixtures must never be presented as real metrics.

## Deployment configuration

Apply `npm run db:migrate`; build web and run web plus worker. Set `DEMO_MODE=false`, canonical HTTPS `NEXT_PUBLIC_APP_URL`, matching X OAuth callback in X developer portal, X OAuth credentials, `X_BEARER_TOKEN`, verified provider access to contributor `impression_count`, `LIVE_COLLECTION_APPROVED=true`, and Operations collection enabled. Configure HTTPS `SOLANA_RPC_URL`, explicit `USDC_NETWORK` (`devnet` for current staging; `mainnet` only under accepted live gates), signer-capable platform `USDC_FUNDING_ADDRESS`, and operator-approved integer `USDC_MICROS_PER_1000_IMPRESSIONS`. Leave rate empty until pricing is approved. Funding stays disabled; drafts remain available. Set `X_TRACKING_V2_SETTLEMENT_ENABLED=true`: without it Studio launches and deposits are unavailable and settlement pauses with funds staying reserved. Studio funding does not need launchpad or automated SOL payout switches. Restart web and worker after configuration changes.

USDC has six decimals. Available/reserved ledger is append-only and separated by network. Wallet-signed deposits require finalized transferChecked to canonical USDC mint and platform associated token account, exact amount, verified source signer, time-bounded intent, unique signature, and memo `useRAID:usdc:<transferId>`. Single receipt cannot credit twice. SOL pays deposit network fees, not Raid budget. Operator pays outgoing network fees; platform campaign fee is zero in v1.

Launch freezes quote and network, atomically reserves available funds, and validates all public targets. Concurrent launches/withdrawals cannot overspend. Quote changes require creator review. Target posts added while live qualify only for contributions created after addition. Drafts survive deposit return and provider outages. Target views never count as participant delivery.

## Qualification, review, CPA

Contributor joins with verified X and wallet before posting. Own-author original post linking a selected target or quote of that target, plus official mention, must be inside campaign window. Reposts, replies, wrong author, duplicates, retroactive targets, and unrelated content do not qualify. Attention leaderboard uses best ten qualifying posts; USDC rewards use all qualifying contributor impressions. Missing views mean unavailable, never fabricated zero. Campaign closes on target or duration. Final collection, two-hour disputes, and corrections precede immutable reviewed allocation. Unknown views or unresolved issues hold allocation.

Earned pool = budget × min(reviewed impressions, target) / target. Each participant receives earned pool × their qualifying impressions / all qualifying impressions. No single participant earns more than the author cap (`RAID_AUTHOR_CAP_BPS`, default 2,500 basis points = 25%) of the funded pool; the cap is frozen on the Raid when it launches, and any excess is redistributed pro rata to uncapped participants before the remainder returns to the creator. The Raid creator cannot enroll in or be paid from their own Raid. A reward below the minimum (`USDC_MIN_REWARD_UNITS`, default 0.10 USDC) is credited to the raider's available balance as a paid `REWARD_CREDIT` transfer instead of entering the manual payout queue; the raider withdraws it once the balance reaches the withdrawal minimum. Integer rounding dust and unearned pool return to creator balance. Over-delivery never enlarges budget. Content CPA = reviewed earned pool / qualifying original-or-quote posts. CPM = reviewed earned pool × 1,000 / reviewed impressions. These measure observed delivery, not guaranteed reach, unique viewers, conversions, or purchases. Campaign CSV labels provisional data and suppresses USDC CPA/CPM until reviewed, with complete views.

Ending a Raid early closes posting and enrollment immediately. If participants have already posted, already-qualified posts keep being measured until the originally scheduled end (`measureUntil`), hourly and once more at that time, and settlement uses those views; the funds stay reserved until then (up to seven days for a 168-hour Raid), then unearned USDC returns to the creator. Measurement stops early when observed impressions already reach the target. Measurement reads are X lookups and count against the X budget.

Deposits and withdrawals have minimums (`USDC_MIN_DEPOSIT_UNITS`, `USDC_MIN_WITHDRAWAL_UNITS`, both 1 USDC by default) and a cap on open requests (`USDC_MAX_OPEN_DEPOSITS`, `USDC_MAX_OPEN_WITHDRAWALS`, both 3).

Creator access is self-serve for signed-in users with a connected X account. Suspended users cannot save drafts, preview targets or launch. Target-post lookups for drafts reuse previews validated within 24 hours and are limited to `STUDIO_LOOKUPS_PER_DAY` (default 300) per creator.

## Manual payouts

After allocation, Operations lists USDC rewards and withdrawals with network, mint, destination, amount, and required memo. Operator reviews, sends transferChecked from platform wallet to recipient associated token account, includes exact memo, then verifies finalized receipt. App never holds outbound signing key. Pending withdrawal reserves available funds; rejection needs audit reason and restores funds. Reward payments do not credit creator balance. Old SOL Raids preserve old funding, qualification, and payment paths. Keep funds reserved for unpaid liabilities; the **USDC reconciliation** card in Operations compares ledger liabilities (available plus reserved, raider credits included) and reward transfers awaiting payment with the custody wallet's USDC balance, and the worker logs a `usdc-deficit` alert hourly when custody falls short. Check it before withdrawing platform capital. `npm run tracking:audit` also reports these obligations read-only: ledger balances per network, USDC transfers by kind and status, unpaid reward allocations, and the pools reserved on live USDC Raids.

Rejecting a withdrawal first checks the chain for a finalized payment matching that withdrawal and refuses with a 409 when one exists; verify that signature instead. Never send a payment while a rejection is in progress. The check needs `SOLANA_RPC_URL` and answers 503 when the history cannot be ruled out.

A genuine deposit that finalized after its 30-minute intent expired is credited from Operations, under **Expired deposit intents**, with the transaction signature and an audit reason. The receipt must still match the memo, amount, wallet and recipient, and the transaction must postdate the intent; only the expiry is waived. A signature settles one transfer only.

Operations shows **Release reserved pool to creator** on a funded Raid that is hidden, whose creator is suspended, or that is held. It returns the whole reserved pool (USDC) or records a full refund row (SOL) and ends the Raid as `HELD_RESOLVED`; raiders' accrued views on that Raid are forfeited. It shares the `raid-settle:<id>` ledger key with settlement, so a release and a settlement cannot both happen. To pay raiders instead, restore the campaign or creator so normal settlement resumes.

Token name, symbol and image are snapshotted on each Raid from what its creator submitted. The shared token record only becomes authoritative once the market provider has supplied them (`metadataSource = MARKET`); until then token pages are labelled unverified.

A verified wallet can be changed from Account (**Change wallet**), signing with the new wallet while signed in with X. It needs a connected X account, no open withdrawal or live deposit intent, and at most one change per 7 days; withdrawals pause for 24 hours afterwards. The old address stops working for sign-in. Raids already joined keep paying the wallet recorded at enrollment.

## Rollback

Migration adds fields/tables and defaults legacy campaigns to Studio version zero/SOL; no existing data rewrite. Disable live funding by clearing rate and deployment gate. Do not drop new tables or delete balance entries. Finish/reconcile pending deposits and transfers before changing network or platform wallet. New network does not expose old-network available funds. Reverting application to older revision stops new Studio launches but cannot settle existing USDC obligations: retain current worker/payment operations until all obligations resolved.
