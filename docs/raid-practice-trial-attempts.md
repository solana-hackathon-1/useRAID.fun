# Durable private canonical practice starts

T013C2, M1/AG05; R05/R06/R12/R15/R16, P07/D07/D08/D13, I05/I06/I07/I08/I10/I13, AC06/73–75. An unrestricted current own session starts approved safe unpaid practice using its actual pre-existing canonical HUMAN. Exact immutable definition/rubric/tool consent and family-wide attempt history are saved atomically with private audit and original receipt. This does not issue an assessment, rank, permission, work engagement, capacity reservation or financial obligation. Actual submission/evaluator/assessment/API/UI and full T013 remain separate work.

## Versioned interface and ownership

Import `startPracticeTrial`, `readPracticeTrialStart`, `PracticeTrialStartRecordSchema`, `StartPracticeTrialInputSchema`, types and `PracticeTrialAttemptStorageError` from `src/skills/practice-trial-attempt-storage.ts`. Portable code owns the command/query and SQL; it imports only Zod and owned contract/receipt/practice/taxonomy modules. No Next, Prisma, environment singleton, external provider or execution tool is imported.

Start accepts `{actor:{accountId,sessionHash}, input, idempotencyKey, requestId}` and server-owned `{allowNewWrites:boolean}`. Input reuses strict v1 `PracticeTrialAttemptInputSchema`: `{version:'v1', definitionReference:{recordId,revision}, accommodationReference}`. Stored revisions are positive INTEGER. Caller-provided participant/history/count/time/rank/approval/persistence fields are rejected. A PREPARED pure result is never a persisted authority or an input substitute.

The exact current saved AVAILABLE definition is required. Its unchanged complete v1 payload includes skill/domain/intended rank, original global rubric/version/criteria, variant, public/synthetic material, tools/AI disclosure, time expectations, limits and accommodation policy. Current actual catalog must still contain the active same skill/domain. Count and latest start derive from immutable actual starts for `(canonical participant, stable trial ID)` across every definition revision. New published limits/cooldown apply to new intent without rewriting any start. A current limit below the already used count rejects new intent. Different own linked sessions use the same canonical history.

Non-null accommodation references explicitly return `ACCOMMODATION_UNAVAILABLE`; no approved scoped durable accommodation authority exists yet. Supporting the ordinary unaccommodated start does not complete accommodation acceptance. Time expectations remain expectations; this command invents no hard submission cutoff. Actual future submission/timeout/cancellation policy must come from approved contracts.

Return `{status:EXECUTED|REPLAYED, start}`. Strict frozen start DTO contains v1, UUID `id`, historical `state:STARTED`, actual `participantId`, full immutable `definition`, actual current `taxonomyReference` at start, `accommodationReference:null`, canonical `attemptNumber`, database millisecond UTC `startedAt`, `persisted:true` and false `verifiesSkill/isAuthorizationToken/createsPermissionGrant/consumesCapacity/createsFinancialObligation`. STARTED identifies the historical start, not current active/submitted/expired state or an admission token. No assessment/verified fact can be inferred from intended target rank.

`readPracticeTrialStart(tx, actor, id)` returns the actual own canonical saved start or null for missing/foreign UUIDs, after current authorization. Malformed UUID is INVALID_INPUT. It never lets a caller supply a participant or query someone else's history. Original definition/rubric and catalog reference survive later publication/retirement; a read grants no evaluator or artifact access.

## Dependencies, authorization and atomicity

Host supplies Node≥22.12, Zod4/shared bs58 dependency, PostgreSQL16, canonical User/Session and actual immutable Participant HUMAN mapping/composite `(id,accountId)` key, existing receipt/catalog/practice migrations and additive29 `202610150002_practice_trial_starts`. Host owns real READ COMMITTED interactive transactions, finite statement/lock/transaction bounds, whole retries and current server-derived actor. A port descriptor is not proof of a real transaction: the host must actually BEGIN/COMMIT/ROLLBACK and preserve all SQL/lock semantics. No external network/model/signature/finality wait belongs under locks.

Start/replay/read require actual unrestricted User, own live wallet/X Session, and an actual pre-existing canonical HUMAN mapped to that account. No role, token purchase, publisher permission or new participant is created. Missing mapping is RESOURCE_UNAVAILABLE. Foreign/revoked/expired/unsupported sessions and suspended accounts deny. Known canonical identity is not a guarantee that unrelated accounts belong to unique humans. Session row locks and database-clock expiry are rechecked after waits and before returning; revocations committed before locks are observed, and subsequent row changes wait for completion.

Lock order: receipt → User NO KEY UPDATE → Session SHARE → Participant SHARE → catalog advisory12012/current SHARE → trial advisory12013/current SHARE → canonical participant/trial history advisory12015. Family history mutex covers bootstrap and every definition revision; hash collisions only serialize unrelated keys. Pure preparation consumes the just-read locked history synchronously with the same database clock. Its one-millisecond validity interval is an internal same-call observation marker, never a transferable freshness assertion or deadline. Actual authorization is rechecked afterward.

Additive `PracticeTrialStart` stores exact definition UUID/current taxonomy version, canonical mapping, family sequence/time and receipt/request. Immutable version FKs retain full consent without duplicating or rewriting definition bytes. SQL uses the same lock path, validates actual current available definition/relevant active taxonomy, ordered bounded family count/cooldown, actual receipt/start chronology, composite canonical identity, matching finalized own `StartPracticeTrial` receipt/private audit and no outbox. Every UPDATE/DELETE, including no-op UPDATE, is denied. Deferred final checks ensure versions remain current through commit; all denied effects roll back together. Privileged SQL is not an alternate session authorization API: current cookies/session policy belongs to the guarded module/host.

Exact duplicate intent has one immutable result and one start. Changed normalized body with the same key fails IDEMPOTENCY_KEY_REUSED after current authorization. Original authorized replay/read survives later retirement, changed limits and disabled new writes. Removing current session/restricting the account denies replay and reads; history remains. Unknown commit success must retry the original key/body; classified serialization/deadlock retries rerun the entire callback, never only the insert.

Private `skill.practice_trial_started.v1` audit uses the start UUID as aggregate, version1, and identifier-only `{practiceTrialStartId}`. No answer, submission, evidence URL, full definition, target/assessed rank, notification/public feed or outbox is emitted. No capacity table or financial balance is touched. Signals should be command/request/error category, duration/retry count; do not log cookies, session hash, complete private start/history or content.
