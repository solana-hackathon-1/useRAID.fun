# Current own practice-review assignment inbox

This bounded T013 interface lets a current evaluator discover finite appointments and open existing scoped case/finding forms. It implements R06/R11/R12/R15/R16, I05/I06/I10/I11/I13, D07/D08/D13 and AC04–07/AC42–43/AC70/AC73–75; [task/evidence](tasks/2026-10-21-T013-review-inbox.md) records actual verification and missing independent/full-task acceptance. The existing [assignment](raid-practice-review-assignments.md), [case reader](raid-practice-review-reads.md), [ownership form](raid-practice-ownership-ui.md) and [assessment form](raid-practice-assessment-ui.md) remain authoritative.

## Authority and privacy

`listPracticeReviewInbox(tx, actor, input, canDiscover)` in `src/skills/practice-review-inbox-storage.ts` lists only current own unexpired/unrevoked `PracticeTrialReviewAssignment` rows. An ordinary current wallet/X session may see its own appointment metadata under the host's explicit synchronous `canDiscover({accountId}) === true` policy. No administrator or holder role gives access to another evaluator's list. This metadata authorization is separate from the exact-submission/purpose policy for private evidence or recording findings. An appointment's presence is neither case-read approval nor a claim that review work is pending, finished or paid.

The strict input is `{version:'v1', after:UUID|null}`; UUID cursor case is normalized. The strict public page has `version:'v1'`, `private:true`, `isAuthorizationToken:false`, `accessId`, `observedAt`, `entries` and `nextCursor`. Each entry contains only `assignmentId`, `submissionId`, `purpose`, `issuedAt` and `expiresAt`. No evaluator/subject identity, issuance reason, title, definition/rubric, private answer/declarations, policy, findings, rank or total counts are selected by listing. The internal `{accountId,page}` host result binds the actual actor and is removed from the wire. Unknown or incoherent host fields fail closed; a schema does not prove authorization by itself.

Every authorized attempt uses a server-generated UUID and commits a `ListPracticeReviewInbox` receipt plus `skill.practice_review_inbox_access_authorized.v1` private audit before appointment selection. Aggregate/actor are the current account; payload is empty. The trace describes an authorized access attempt, not delivery. No outbox or business state changes occur. Audit failure prevents selection; thrown failures roll back. Initial authorization/policy denial writes no trace. Never log cookies, private SQL diagnostics or response bodies.

The host supplies a guarded PostgreSQL READ_COMMITTED transaction, actual identity/assignment/revocation tables and prior migrations, current synchronous policy, database time, bounded driver, rollback/whole retries and commit-before-delivery. User/Session locks are reused from the canonical skill boundary. Assignment issue/revoke commands acquire the same evaluator User lock in their existing sorted multi-user order. Discovery holds only its own User/Session locks and takes no appointment advisory locks, so it introduces no reversed multi-user lock order. Actual current session and policy are repeated after audit and selection waits; a final database clock/session observation removes appointments that expired during waits. Revocation committed before observation is excluded; a revocation blocked behind the held User lock takes effect after commit and is absent on the next observation. This is a point-in-time observation, never a permission lease or a claim that disclosed bytes can be recalled.

## Bounded pages, HTTP and UI

Rows are ordered by UUID ascending with a fixed20 entries and one lookahead; the next cursor is the final returned ID only when another current own row exists. Cursor is an ordering position, not authorization, and may be freely supplied without selecting another account. No cross-account IDs or counts arise from a foreign cursor. Refresh from the first page to see new appointments whose random UUID precedes the cursor. Pagination is not a snapshot: additions/expiry/revocation may change later pages, and an empty later page does not claim the account has no earlier appointments. Expiry can shrink a page during the final check. The policy never parses or fetches submission content; exact-case policies run independently on open/save.

`createPracticeReviewInboxHandlers(host)` in `src/skills/practice-review-inbox-http.ts` uses native Web Request/Response and explicit version/requestId/current actor/account quota/list ports. Protected `GET` and `HEAD /api/v1/practice/reviews[?after=UUID]` authenticate/limit before input validation. Repeated/unknown query fields, actor/limit/purpose selectors and invalid cursors fail422. Errors are sanitized401/403/422/429/503 envelopes; unexpected/misbound host output or a postcommit disabled/invalid envelope returns503. All handler responses use `Cache-Control: private, no-store` and `Vary: Cookie`; HEAD performs the same checks/audit and drops its body. Unsupported method dispatch returns405. Root's framework-generated OPTIONS/unsupported methods have no private payload; the handlers do not supply CORS permission. GET/HEAD need no mutating user command or CSRF key; cross-site attempts can create audit noise under existing browser cookie policy, but cannot read private responses.

Root `src/lib/practice-review-inbox.ts` composes actual `requireUser`, current cookie/hash and the existing shared `practice-review:{accountId}`30/60 account quota. It injects the existing exact-true/default-off `PRACTICE_REVIEW_READS_ENABLED` gate and repeats it after the transaction commits, dropping metadata if it closed. A currently disabled metadata policy denies403 before selection; a postcommit closure returns the disabled503 envelope. There is no new product flag, schema, real appointment, provider effect or gate enablement. Case and finding routes retain their own actual current actor/assignment/purpose/approved policy/CAS checks and audit. Turning off discovery does not delete immutable appointments, private evidence/history, receipts or separate owner access.

`createPracticeReviewInboxLoader(get)` accepts a native injected protected GET dispatcher; no self-HTTP network call, cache or duplicate domain rules. It maps current responses to READY/SIGN_IN/DENIED/RATE_LIMITED/UNAVAILABLE/NOT_FOUND and rejects malformed/mismatched success. `PracticeReviewInbox({state})` is a portable stateless React view with type-only dependency on loader state. Host must authorize and canonically validate data before rendering. It renders semantic list/headings, explicit UTC timestamps, native refresh/next links, empty/error states and exact-purpose case/finding links. Native anchors do not prefetch private cases. Root dynamic Node `/evaluator/practice` supplies generic noindex metadata and loading UI. Production HTML must be private/no-store; installed Next's development HTML header is no-cache/must-revalidate and all preview records are synthetic. React/ReactDOM and the host's existing `studio`, `stack`, `panel`, `button` theme are explicit dependencies. Root browser checks verify theme/layout; independent SSR verifies semantics, not WCAG conformance.
