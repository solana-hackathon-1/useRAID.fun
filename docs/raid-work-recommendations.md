# Bounded difficulty and reward recommendations

T017 gives Founders explainable advice while they keep control of every term. `recommend` turns bounded Founder-entered signals and a host-supplied, versioned rubric into a structured estimate: difficulty E–S, per-skill minimum ranks with verification required, routed participant kinds, a reward range in the exact asset's base units, an estimated duration range, confidence, assumptions and missing information. It is advice only: `authoritative` is always `false`, and nothing here publishes, prices, reserves or accepts anything. Persistence of suggestions, the HTTP route with its budget and rate cap, and the creation wizard (T018) are separate work.

## Contract and requirements

| Requirement                            | Implemented behavior / verification                                                                                                                                                                                                                                                                                                                                                                               |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R07, blueprint §11.3                   | Deterministic, pure scoring of integrations, skill domains, dependencies, effort, uncertainty, consequence of error, verification cost and deadline pressure with the rubric's weights and thresholds; routing and duration complete the assistance flow. Historical comparable work and qualified capacity are not available and are always listed as missing, so confidence is `LOW` or `MEDIUM`, never `HIGH`. |
| R05                                    | Every estimate carries an E–S difficulty and explicit skills; the primary domain requires the difficulty rank, supporting domains one rank lower, all with verification required.                                                                                                                                                                                                                                 |
| I03, blueprint §11.4                   | Rewards are exact base-unit ranges for the asset policy the Founder selected. No asset is chosen for them, no fiat value is claimed (`priceReference` is `null`), and an asset with no reviewed price basis yields `UNAVAILABLE` plus a targeted missing-information entry instead of a made-up range.                                                                                                            |
| P08, blueprint §11.4                   | `reviewChoices` keeps the original suggestion beside the Founder's final choices, marks each field accepted or edited and explains every gap (difficulty, skills, participant kinds, reward below/above range or in another asset, price unavailable, deadline shorter than the estimate). A gap never blocks.                                                                                                    |
| I08, I10, §11.4 "model cannot approve" | `validateModelAdvice` accepts only a summary, known skill hints and a difficulty hint, as `UNEVALUATED_MODEL_ADVICE` with `authoritative: false`. Amounts, asset addresses, escrow instructions and accepted terms are rejected as unknown keys. Publication is still decided only by the typed terms checks.                                                                                                     |
| R15/R16                                | Strict version-one schemas, no I/O or clock, no default rubric in `src`. The example rubric is an `UNEVALUATED_EXAMPLE` fixture; a `REVIEWED` rubric must carry its review reference and an example must not. The independently installed work-loop host calls the module against its own fixture.                                                                                                                |

Requirement mapping: T017 uses AG03/AG02, M2, R05/R07, P08, I03/I08/I10 and blueprint §§08, 11–12, 16, 23, 26. The example weights, bands and thresholds in the fixture are not market quotes, fees or production thresholds; no real rubric, price source or comparable-work evidence is selected, so any production use stays NOT VERIFIED until a reviewed rubric (`reviewRef`) is supplied. Full numbered task criteria, UAT and release approval remain NOT VERIFIED.

## Public module interface

`recommendation.ts` exports `recommend(input, rubric)`, `reviewChoices(recommendation, finalChoices)` and `validateModelAdvice(raw, knownSkillIds)`; `recommendation-contracts.ts` exports their strict schemas. All throw `WorkError('INVALID_INPUT')` for malformed input or rubric, with no partial result.

## Operation and verification

There is no state or migration. `tests/work-recommendation.test.ts` verifies the structured estimate and its determinism, rising difficulty/routing/uncertainty, honest missing-information and unpriced-asset behavior, malformed input and rubric review labelling, accept/edit/gap reporting with the retained original, model-advice rejection of price/asset/escrow keys, and that advice never changes the typed publication checks. Test names and genuine RED/GREEN results belong in the PR; this task is non-risky and closes on CI plus the PR checklist.
