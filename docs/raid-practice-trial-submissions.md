## Stable interface and immutable consent

Import `submitPracticeTrial`, `readPracticeTrialSubmission`, `SubmitPracticeTrialInputSchema`, `PracticeTrialSubmissionRecordSchema`, `PracticeTrialSubmissionStorageError` and types from `src/skills/practice-trial-submission-storage.ts`. Portable code owns validation, SQL and receipt commands with Zod/owned shared contracts only; no Next, Prisma, app database/environment, SDK or provider is imported.

Submit `{actor:{accountId,sessionHash}, input, idempotencyKey, requestId}` with trusted server-owned `{allowNewWrites:boolean}`. Strict v1 input is `{version:'v1', startId, expectedDefinitionReference, expectedRubricReference, answer, explanation, toolsUsed, aiAssistanceUsed, assistanceDisclosure}`. Start is UUID; expected references must match the actual accepted immutable start. A later definition/rubric cannot replace its original consent. Caller participant, ownership/assessment, evidence, author/time, persisted and result-reference fields are rejected.

Answer is nonempty visible plain text≤40000 UTF-16 units; explanation/disclosure each≤4000. Preserve exact whitespace, line endings and Unicode sequences in all three fields; trim is used only to detect empty-visible content. Tool labels are normalized by trim, unique,0–50 and≤200 UTF-16 units each. AI use is a strict boolean, not truthy input. PostgreSQL NUL/lone surrogates and unsupported reference ranges reject before SQL. The shared normalized serialized-request limit≤65536 characters additionally applies. These are technical storage bounds, not capability grading or retention policy. Installed Zod4.6.5 string max counts code points; explicit string.length refinements enforce the declared stored UTF-16 bounds and match SQL without changing accepted response text.

Return `{status:EXECUTED|REPLAYED, submission}`. Frozen strict DTO contains v1, `reference:{recordId:UUID,revision:1}`, actual start UUID/canonical participant, original skill/domain/definition/rubric references, historical `state:SUBMITTED`, database millisecond UTC `submittedAt`, exact answer/explanation/disclosure, normalized tool labels/declared AI use, `ownership:UNCONFIRMED`, `persisted:true`, and false `verifiesSkill/isAuthorizationToken/createsPermissionGrant/consumesCapacity/createsFinancialObligation`. A user declaration is not originality/compliance confirmation. Declared deviations can be recorded for an authorized reviewer to assess against the original policy; they are never silently approved or interpreted as fraud/rank. No self-asserted text or intended target rank becomes a committed eligibility fact.

One final response per saved start is fenced by SQL. Another attempt uses the existing start command and actual published family limits/cooldown. Silent final-response edits, requested revisions and reviewed amendments are separate transitions. This immutable submission never changes the historical STARTED record into a claim about current lifecycle; future projections combine actual start/submission/decision records. Published time expectations do not authorize an invented hard cutoff.

The additive `lockPracticeTrialParticipant(tx, actor)` export from start storage reuses current locked ordinary account/session and real canonical mapping, returning the frozen actual own HUMAN only. Submission reuses this identity boundary and the actual protected original-start reader; lower owned reader denials are normalized to the submission command's error class while preserving authentication/restriction codes.

Start must actually belong to that canonical account/participant. Foreign and missing starts both return RESOURCE_UNAVAILABLE; ordinary caller, role-only admin, token holder or client flags cannot obtain another subject's private body. Current revoked/expired/foreign/unsupported sessions and suspension deny new intent, original replay and private reads. Role/publisher permission is not a private-submission grant. Session database-clock expiry is rechecked after waits and before returning; revocation committed before acquisition is observed, and later row revocations wait for commit. Unknown success retries the exact original key/body; preserve intent at the caller. Changed answer whitespace is a material digest change, never normalized away. Different body with the same key returns shared IDEMPOTENCY_KEY_REUSED only after current authorization. Never issue a fresh key to resolve unknown commit success or retry only an insert. Driver deadlock/serialization failures rerun the entire callback with original identity.

## Storage, privacy and operating limits
