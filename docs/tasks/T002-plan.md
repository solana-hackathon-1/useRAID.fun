## Acceptance and verification defined before coding

T002-A01/W01: one public barrel consumed by a minimal independently runnable host and contract tests; no imports of RAID database/config/session/provider state. Strict DTOs, branded IDs and exact strings cover all six named contracts. T002-A02: reject work-as-payment/access/dispute/transaction confusion. T002-W02: complete state-vocabulary ownership matrix and command register; policy-dependent financial/dispute transitions stay documentary, not an executable generic state setter. T002-W03: version `/api/v1`, revisions/expectedTermsVersion/idempotency metadata, safe reason-code envelope and total lock-order plan.

Write tests before implementation. Capture actual RED failure, then GREEN with the same assertions; refactor and run relevant legacy states/amounts, docs, planning and static checks. New `tests/**/*.test.ts` tests are discovered by existing CI. Required exact-candidate GitHub jobs: planning-contracts, static, dependency-security, test (real disposable PostgreSQL legacy regression), docker, browser, ci-gate. New contract-only behavior needs unit/schema/type and independent consuming-host checks; real DB/program races, adapter switching, private downloads, browser/UAT and live gates are owned by the consuming feature tasks. Broad passing regressions do not verify those missing features.

Independent reviewer must review each of the 27 numbered criteria, including specific exclusions; completion validator must be run and failures retained. No self-approval or invented UAT. No schema migration, deployed-obligation audit, new `/api/v1` route, refactor of existing money/auth/provider code, treasury signing, staging deployment, PR merge, board Done or issue closure. T003 plans compatibility before persistence; T019/T020/T029/T089 implement commands/constraints/registry/API gates. Existing historical obligations and accepted policy snapshots stay untouched.
