# T019 idempotent command receipts, audit and outbox — acceptance before implementation

Owner: Claude Sonnet 5.5 (AG03 backend/domain), delegated by the orchestrator. Milestone M2 / S03, [issue #61](https://github.com/solana-hackathon-1/useRAID.fun/issues/61). Baseline `101348a` (`origin/main`), branch `claude/t019-command-receipts`. Dependencies T002 (shared contracts) and T003 (migration plan, phase P3) are merged.

Outcome: a reusable, replaceable foundation that makes one logical command produce one business outcome. It persists `actor + command kind + client idempotency key` with a canonical request digest and a result reference, commits the caller's state change together with append-only audit events and outbox intents in one transaction, and deduplicates incoming provider deliveries by `provider + verified delivery id`. This is **not** a business command: nothing is wired into existing routes, no worker delivers outbox rows, no provider is called, no existing table or migration changes.

## Authority and mapping

Direct requirements: AC32 (foundation level: duplicate delivery gives one outcome), AC69, I05, I09 (intent recorded before external effect; no pretended atomicity), I08 (receipt binds the exact request digest), I13, R15, R16, AC73/AC74/AC75. Blueprint 26.1 (idempotency key scoped to actor and operation, stored request digest and response reference), 27.1 event envelope, 27.3 (state, audit, receipt and outbox in one transaction; at-least-once; inbox with unique provider delivery ID), 27.5 (deduplication keys), 24.6/24.7 (module contract), 25.6 (`command_receipts`, `audit_events`, `outbox_events`, `webhook_inbox` named by ownership), 32.2 (real concurrency). T003 phase P3 governs the additive migration. LOCKED: R13, R15, R16. DEFAULT: D01 modular monolith with PostgreSQL outbox. OPEN items untouched (O18 hosting, O11 retention). Not touched: R13 capacity itself (T020 consumes this foundation), money, access, UI.

Shared contract reuse (`src/contracts`): `InternalId` for every identifier, `EventEnvelopeSchema` for event type/aggregate/payload validation (identifier-only payload, strict), `ERROR_CONTRACT.IDEMPOTENCY_KEY_REUSED` for the HTTP mapping of the conflict. The T002 lock plan puts the receipt first in lock order; the module claims the receipt before the caller's callback runs.

## Design decisions

| Decision          | Choice and reason                                                                                                                                                                                                                                                                                                          |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Receipt claim     | `INSERT ... ON CONFLICT DO NOTHING` on the unique `(actorId, commandKind, idempotencyKey)` index **before** the business callback. A concurrent identical command blocks on the unique index until the first transaction ends, then replays (committed) or proceeds (rolled back). No application mutex, no advisory lock. |
| Result reference  | Opaque `InternalId`, never a payload (I06). Written once after the callback (`NULL` to value); a deferred constraint trigger makes a receipt without result impossible to commit.                                                                                                                                          |
| Request digest    | SHA-256 over a canonical JSON form (sorted keys, no `undefined`, no bigint/Date/NaN). The caller must include everything that defines the command, including the expected terms version (I08).                                                                                                                             |
| Rejected commands | A deterministic business rejection or any error rolls back the whole transaction: no receipt is stored, a later retry with the same key is evaluated again. Only committed outcomes replay.                                                                                                                                |
| Isolation         | READ COMMITTED (same as identity storage). The port verifies it. Deadlock (`40P01`), serialization (`40001`) and Prisma `P2034` are classified `RETRY_TRANSACTION`; the host helper retries the **whole** transaction with the same command identity.                                                                      |
| Audit/outbox      | One `AuditEvent` per event (append-only, trigger-enforced); an `OutboxEvent` with the same event id unless the event is marked non-publishing. Delivery state is deliberately absent: a later worker task adds a side table.                                                                                               |
| Inbox             | `InboxDelivery` unique `(provider, deliveryId)`, payload stored only as digest. Same delivery, same digest: duplicate, handler not run. Same delivery, different digest: `DELIVERY_PAYLOAD_CONFLICT`, original untouched.                                                                                                  |
| Retention         | No delete path in v1; retention is OPEN (O11).                                                                                                                                                                                                                                                                             |

## Acceptance defined before coding

| ID                               | Observable result                                                                                                                                                                                                                                                                                                                                 | Evidence (test file : behavior)                                                                                                                   |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| T019-A01 / W01 / AC69 foundation | Same actor+kind+key and same digest returns the original `resultRef` and receipt id; callback runs once.                                                                                                                                                                                                                                          | `command-receipts-db`: sequential replay; 8 parallel identical commands via the retry helper: one `EXECUTED`, seven `REPLAYED`, one business row. |
| T019-A02 / W02 / AC69            | Same key with a different payload fails `IDEMPOTENCY_KEY_REUSED`; the original receipt, audit, outbox and business rows are byte-identical afterwards.                                                                                                                                                                                            | `command-receipts-db`: sequential and concurrent (after the first commits) conflict with before/after snapshot.                                   |
| T019-W03 / I09                   | Business row, receipt, audit and outbox commit together or not at all (callback error, invalid event, invalid result reference). Audit and outbox are append-only. Deferred trigger rejects commit without a result reference.                                                                                                                    | `command-receipts-db`: rollback matrix; DDL guard tests with raw SQL.                                                                             |
| AC32 foundation / I05            | A provider delivery repeated sequentially or concurrently produces one callback run and one business row; changed payload conflicts; same id under another provider is independent; failed callback releases the claim.                                                                                                                           | `command-receipts-db`: inbox suite.                                                                                                               |
| Concurrency (C11)                | Two competing real transactions with the same key: second is observed blocked on the first's backend through `pg_blocking_pids`, then replays; if the first rolls back the second executes. Real deadlock between two different commands gives one abort `40P01`, whole-transaction retry, identical semantic identity, exactly one receipt each. | `command-receipts-db`.                                                                                                                            |
| Privacy (C09, I06)               | Secret strings placed in the request or provider payload appear in no table; event payload with unknown or free-text fields is rejected before SQL.                                                                                                                                                                                               | `command-receipts-db`, `command-receipts`.                                                                                                        |
| Validation and sanitization      | Bad IDs, kinds, digests, events and ports fail with typed codes before any SQL; driver messages never surface.                                                                                                                                                                                                                                    | `command-receipts` unit.                                                                                                                          |
| Retry helper                     | Retries only `RETRY_TRANSACTION`, bounded, same identity each attempt, passes other errors unchanged.                                                                                                                                                                                                                                             | `command-receipts` unit, `command-receipts-db`.                                                                                                   |
| Substitution (C20, AC73)         | A scripted alternate port serves replay/conflict without Prisma; capability gap (wrong dialect/isolation) fails closed.                                                                                                                                                                                                                           | `command-receipts`, example host.                                                                                                                 |
| Reuse (C21, AC74)                | Public module has no Next/Prisma/env/global/app import; standalone host with its own dependencies and schema runs against a disposable database; docs list the R16 sections.                                                                                                                                                                      | `command-receipts-boundary`.                                                                                                                      |
| CI (C22)                         | All four new test files registered in `planning/raid-ci-matrix.json` (inventory and E06).                                                                                                                                                                                                                                                         | `raid-evidence` test, matrix edit.                                                                                                                |

Out of scope and unchanged: capacity commitments, terms, escrow, access, HTTP routes, `/api/v1` handlers, UI, outbox worker or dispatcher, provider calls, backfill, retention jobs, existing `Job`/`ModerationEvent`/`FinancialTx` tables.

## Criteria disposition (implementer view; reviewer decides)

C01–C03, C05, C10–C12, C14–C16, C18–C22, A01–A02, W01–W03: implementer evidence supplied in `planning/task-evidence/T019.json`, all `NOT VERIFIED` until a distinct reviewer inspects. C04: no actor-by-resource authorization is added; the host authenticates the actor (documented). C06: no capacity consumed; lock-order slot (receipt first) respected. C07: the digest binds the exact request including expected terms version; no amendment command. C08: no financial obligation touched (proposed N/A). C09: identifiers and digests only. C13 and C17: no user-facing surface (proposed N/A). C15: no feature flag needed because nothing is wired in; rollback is unused additive tables (below).

Rollback: before any consumer writes, the migration can be reverted by dropping the four tables and three functions. After acknowledged receipts exist, retain the tables and triggers: dropping them loses idempotency memory and audit history (T003 rule: never drop receipt tables after acknowledged commitments).

Independent review remains required; this packet never marks C-level review criteria PASS.
