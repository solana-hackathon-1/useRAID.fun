## Two distinct hosting contracts

`sites/coming-soon/` is plain HTML/CSS/local fonts. [The static deployment guide](../coming-soon-deploy.md) sets Pages root `sites/coming-soon`, preset None, build `exit 0`, output `.`, and `SKIP_DEPENDENCY_INSTALL=1`. The existing provider project must be inspected before assuming these values are active. Cloudflare's [static HTML guide](https://developers.cloudflare.com/pages/framework-guides/deploy-anything/) supports a buildless static site. This path hosts the placeholder only.

The application uses Next route handlers, PostgreSQL, Prisma migrations, sessions and a durable worker. Its portable contract is the existing root `Dockerfile`: clean npm install including the local security fork, production build, runtime Prisma/tsx, non-root Node process; web `npm run start`, worker `npm run worker`, deployment migration `npm run db:migrate`. Web checks `/api/health`; a successful web health check alone proves neither worker progress nor database durability. Source: `railway.toml`, `railway.worker.toml`, `src/worker.ts`, `src/lib/queue.ts`, `src/app/api/health/route.ts`, `.env.example`, [operations](../operations.md). Static Pages settings cannot run this topology.

## Concrete environment preparation

Use a separate staging database, provider installations, storage, callbacks and keys. Do not import production rows or signer keys into test fixtures. Initial staging evaluation keeps `DEMO_MODE=false`, `LOCAL_AUTO_APPROVE_CREATORS=false`, `STUDIO_SANDBOX=false`, `ALLOW_REMOTE_TEST_DB=false`, `LIVE_COLLECTION_APPROVED=false`, `X_TRACKING_V2_SETTLEMENT_ENABLED=false`, `LAUNCH_ENABLED=false`, `PAYOUT_ENABLED=false`.
