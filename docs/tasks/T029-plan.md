## Outcome

A reward, funding observation or balance names the exact on-chain instrument (chain, network identity, kind, mint, token program) and never loses precision. A ticker, symbol, image or policy revision can never select, substitute or duplicate an asset. Amounts are bounded `bigint` base units with exact parse/format/add/subtract/split/fee arithmetic and JSON decimal strings. A reward bundle is "fully funded" only when every promised asset leg has verified funds. No asset is supported for production until the OPEN decision O07 and gate G04 supply an allowlist; the shipped allowlist is empty and a production profile containing test, devnet, sample, mock or unlisted assets fails closed.

## Design

New public module `src/asset-registry/` (imports only `../contracts/*`, Zod via contracts; no Next, Prisma, env, global, clock or provider imports):

- `errors.ts` typed `AssetRegistryError` with machine codes (`INVALID_AMOUNT`, `EXCESS_PRECISION`, `AMOUNT_OVERFLOW`, `AMOUNT_UNDERFLOW`, `INVALID_ALLOCATION`, `UNSUPPORTED_ASSET`, `ASSET_MISMATCH`, `ASSET_POLICY_CHANGED`, `PRODUCTION_BLOCKED`, `INVALID_CONFIGURATION`). Message is the code only.
- `amounts.ts` bound `U64_MAX`, `parseAmount`, `formatAmount`, `checkedAdd`, `checkedSub`, `sumAmounts`, `splitProportional` (explicit remainder rule `LARGEST_REMAINDER` or `UNALLOCATED`, result discloses residual), `computeFee` (basis points, caller-chosen `FLOOR`/`CEIL`), `toJsonAmount`/`fromJsonAmount`. No floating point; `number` inputs rejected.
- `registry.ts` immutable `AssetRegistry`: networks with a host-declared cluster class, assets keyed only by `assetKey`, display metadata (symbol, name) never used for lookup, versioned policy snapshots per asset (same version and content is idempotent, same version different content or a decimals change is `ASSET_POLICY_CHANGED`), support evaluation of token program and extension profile (default-reject list).
- `bundle.ts` reward legs, verified funding observations de-duplicated by operation ID, per-asset aggregation (policy version is never part of the key), per-asset funding state (`REQUIRED`, `PENDING`, `VERIFIED`, `SHORTFALL`, `BLOCKED`) and `fullyFunded` only when every promised asset is `VERIFIED`.
- `production.ts` `PRODUCTION_ASSET_ALLOWLIST` (empty, O07), `validateProductionConfig`, `createProductionAssetRegistry` (throws `PRODUCTION_BLOCKED` with violation codes).

Persistence (additive, inert, no consumer yet): one migration `prisma/migrations/202610090002_asset_registry/` creating `Asset` (partial unique indexes: token identity; native per network; kind/null checks) and `AssetPolicySnapshot` (FK RESTRICT, unique per asset/version, decimals 0..255, slot 0..2^64-1, immutable rows, decimals fixed per asset by trigger). Justification: T003 requires the exact-asset identity registry before reward-obligation or Guild-token foreign keys, and the AC29/AC30 uniqueness and "version cannot split identity" rules are database-level invariants, not only in-process ones. It touches no existing table, adds no backfill, no legacy USDC mapping and no supported-asset rows.

## Test plan (written before implementation)

1. `tests/asset-registry-amounts.test.ts` exact decimal parse/format round trip; excess precision, floats, signs, exponents, whitespace, leading zeros, empty fraction rejected; upper bound u64 inclusive; checked add overflow and sub underflow; split conservation with both remainder rules and deterministic ties; zero total, negative or empty weights rejected; fee floor/ceil exact; JSON string round trip and `number` rejected. Property-style loops over a seeded PRNG (no `Math.random`).
2. `tests/asset-registry-registry.test.ts` AC29 (two mints one ticker are two assets; wrong network rejected; ticker or display never resolves), AC30 (policy version never changes the key; decimals change and conflicting same-version rejected; idempotent re-record), default extension rejection, unknown token program rejected.
3. `tests/asset-registry-bundle.test.ts` AC28 (two-asset reward with one deposit is not funded), same-symbol different-mint deposit does not fund, unverified observation is `PENDING`, duplicate operation counted once, conflicting duplicate rejected, two legs of one asset aggregate with overflow guard, policy-version tagged duplicate not double counted, empty or zero leg rejected.
4. `tests/asset-registry-production.test.ts` AC41 (devnet, test fixture, sample, mock provider, unlisted asset, rejected extension each fail closed; empty shipped allowlist blocks every asset; factory throws).
5. `tests/asset-registry-db.test.ts` (real PostgreSQL) uniqueness for token identity and native per network, kind/null checks, bounds, FK restrict, immutability, decimals trigger, concurrent inserts.
6. `tests/asset-registry-boundary.test.ts` import/global boundary, docs headings, consuming host run, migration directory name and contract-reuse (no redefinition of `assetKey` etc.).

Existing money tests are run unchanged as the regression baseline.
