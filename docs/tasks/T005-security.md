## Consumed compatibility and host boundary

Owned change is repository dependency composition/lockfile and regression tests, not a new reusable authentication/treasury module. Canonical R15/R16 gaps identified in T001 remain gaps. No provider default or in-flight operation is rerouted by this patch. `FinancialTx` signed bytes, blockhash/validity, original signature/provider/network/asset and application semantic operation IDs stay stored and reconciled by unchanged code. JSON-RPC IDs correlate transport requests; they do not authorize settlement or deduplicate a business payout.

Installed Jayson 5.0.0 keeps the CommonJS `jayson/lib/client/browser` constructor/callback interface used by Web3.js. The actual consumer test instantiates `Connection` and supplies only a deterministic injected fetch transport at `https://rpc.example.invalid`, with no production credentials, database or app globals. It verifies exact JSON-RPC method/params, finalized commitment, correlation, one request and preserved RPC rejection. The separate `parseStream` prototype test reproduces library behavior: Web3.js’s HTTP/browser client already uses native `JSON.parse`, so this is not evidence that Solana HTTP responses previously inherited admin privileges.

Hosts require repository Node `>=22.12.0` (CI/container Node 22), npm lockfile semantics, Sharp-supported native platform libraries and modern secure-context browser crypto if the Jayson browser entry is independently consumed. Jayson itself requires Node >=20; browser consumers need native `crypto.randomUUID`/`getRandomValues` or an explicit ID generator. Its server/TCP/TLS parser changed to newline-delimited framing; concatenated unframed JSON is incompatible. No direct Jayson TCP/server consumer was found in application source. It does not add a general input-size limit. Adding such transports requires separate bounded-input, reviver/framing and recovery review.

Run the declared consumer/security example without application credentials:

```sh
npm ci
npx vitest run tests/dependency-security.test.ts tests/audit-check.test.ts
npm run audit:check
```

Dependencies are explicit in the existing package/lockfile: Vitest, Web3.js/Jayson, Sharp/librsvg and source-map-js. The fixture injects transport and imports no RAID singleton, session, treasury or live provider. Node/macOS checks do not replace Linux, real DB, browser or provider-specific gates. This does not establish whole-feature AC73/74 compliance for legacy code.
