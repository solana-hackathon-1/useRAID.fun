# Private owner Guild drafts

T009B under R01–R04/R10/R15/R16, I06/I07/I10/I13 and blueprint06/07/10/13/16/24–30/33/34M1/35AC07,73–75. This module stores only private owner preparation. DRAFT_UNVERIFIED is not a verified Guild, Founder badge, project-control attestation, public listing or delegated role. No identity, history, skill/rank, work/capacity, treasury, settlement or private-code permission changes. Actual project verification belongs to T010; API/UI and full T009/independent review/UAT remain NOT VERIFIED.

## Stable interface and fields

`saveGuildDraft(tx, command, options)` and `readGuildDraft(tx, actor, id)` are exported from src/guild-profiles/draft-storage.ts; pure preparation/projection/policy exports remain independently consumable from index.ts. The host supplies GuildDraftActor with accountId, actorAccountId and the SHA256 hash of the current authenticated cookie. These facts come from server authentication, never browser JSON, a global creator role, token balance or market metadata. Both account IDs must match; only existing own wallet/X sessions are accepted. Current User restriction and Session expiry are checked in the transaction.

SaveGuildDraft takes input `{guildDraftId, expectedRevision, profile:{name,slug,description}}`. Creation uses null ID/revision0; update uses a current UUID/revision1+. Shared public field schemas trim before validation; extra privilege/private fields are rejected. A persisted slug is stable and unique among these drafts. This is a draft namespace reservation, not proof of ownership of an external project name; verified/public slug reconciliation remains a future contract. Multiple owner drafts are permitted, each with its own revision. There is no listing/public read/ownership-transfer/delegation operation in this interface.

The private result is `{status:EXECUTED|REPLAYED,draft:{version:v1,id,state:DRAFT_UNVERIFIED,revision,recordedAt,profile,founderControlVerified:false,publicProfileApproved:false,primaryToken:null}}`. Owner IDs, session secrets, receipt keys, other drafts, private configuration and verified authority are not copied into the response. Unknown or foreign UUIDs both return NOT_FOUND. Reads remain available when new writes are disabled. The host must keep these responses private/no-store and authorize any future transport independently; this module does not install an HTTP route.

## Host dependencies and transaction rules

Inject the existing CommandReceiptTransaction v1 port: actual PostgreSQL, one connection, READ COMMITTED, parameterized query/Date decoding and sanitized retry classification. The host owns begin/commit/rollback, current cookie authentication, origin/rate/body limits for a future API, whole-transaction deadlock/serialization retries and an explicit boolean allowNewWrites (no implicit write default). Minimal host tables are User(id,suspended) and Session(tokenHash,userId,via,expiresAt); expiresAt is the repository's UTC timestamp-without-timezone. No Next/Prisma/provider dependency enters the module. The independent example uses its own pg driver and schema.

Receipt-first ordering then locks User → Session → existing GuildDraft; own session and restrictions stay locked until commit. Authorize with `clock_timestamp() AT TIME ZONE 'UTC'` after row waits, after draft locks, after unique-slug acquisition and on receipt replay. No client clock or transaction-start timestamp supplies authority. A waiting command that expires/revokes/suspends rolls back the entire attempted mutation. The host must commit promptly without unrelated callbacks; expiry is checked at the command boundary, not a promise of perpetual session validity through an arbitrarily delayed host commit.

The actor/kind SaveGuildDraft/key and normalized complete input define the receipt. Same key/body replays the original immutable version after subsequent edits or write-disable; changed normalized semantics returns IDEMPOTENCY_KEY_REUSED. Lost acknowledgment retries retain key/body and do not create another draft. Revision conflicts and SLUG_UNAVAILABLE roll back versions, projection, receipt and audit together. Whole-transaction retry must preserve command identity and never retry an isolated SQL write in an aborted transaction.

## Owned storage, audit and errors

Additive 202610130002_guild_drafts creates GuildDraft plus GuildDraftVersion; prior migrations/history stay unchanged. Restrictive User/receipt and composite owner/version/draft/revision foreign keys prevent pointer substitution. The version-to-draft constraint is deferred only for initial same-transaction creation. Versions are immutable; projection owner/id/slug are immutable and revisions advance sequentially with another version. Structural JSON constraints forbid extra authority/private fields; runtime shared validation owns complete normalized field semantics. No database grant bypass is a replacement for service authorization; privileged database owners retain maintenance powers requiring reviewed recovery.

Every version must commit with its own finalized receipt and private `guild.draft_recorded.v1` audit, exact draft/revision/actor/request and identifier-only `{guildDraftVersionId}` payload. No outbox intent or draft text is published. Audit guildId is null because this draft is not an activated authoritative Guild. Current projection and snapshot slug must match. No new event is emitted for replay.

Typed GuildDraftStorageError codes: INVALID_INPUT, WRONG_ACTOR, UNAUTHENTICATED, ACCOUNT_RESTRICTED, NOT_FOUND, WRITES_DISABLED, REVISION_CONFLICT, SLUG_IMMUTABLE, SLUG_UNAVAILABLE, STORAGE_CONTRACT, STORAGE_UNAVAILABLE. Shared receipt codes retain changed-key conflict and RETRY_TRANSACTION; unknown driver details are sanitized. Hosts must not expose raw driver SQL, private input or cookie hashes in logs.
