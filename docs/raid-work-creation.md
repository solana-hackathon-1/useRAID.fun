# Founder Raid wizard and reward review

T018 lets a signed-in Founder draft a clear task, understand every reward leg, who pays fees and what is actually covered, and publish only when the server says the Raid is valid and fully funded. It is a guided six-step browser flow at `/creator/work/new` over the T016 terms commands, with optional T017 advice. All funding is simulated, every capability sits behind default-off flags, and nothing here grants Guild or production authority. Entry links from existing navigation, Root Guild recognition, real funding and the public listing card surface remain separate work.

## Host contract

Flags are exact-string `true` and default off: `WORK_CREATION_READS_ENABLED` (required for everything), `WORK_CREATION_SAVE_ENABLED`, `WORK_CREATION_PUBLISH_ENABLED`, `WORK_RECOMMENDATIONS_ENABLED`. `RAID_WORK_OPERATOR_ACCOUNT_IDS` (synthetic allowlist, empty denies everyone) and `RAID_WORK_GUILD_ID` (default `synthetic-guild`) stand in for Guild authority. `WORK_REWARD_ASSETS_JSON` is an array of `{label, policy, funded}`; unset or malformed means no asset can be offered or reserved. `WORK_RECOMMENDATION_RUBRIC_JSON` is an optional versioned rubric; without it there is no estimate and no default is shipped. With a flag off the page says so and original receipts still replay.

HTTP (`/api/v1/work/…`, `private, no-store`, bounded JSON): `GET creation` (assets, own drafts with review and readiness, flags), `POST drafts` (`Idempotency-Key`; the terms are re-validated strictly and the saved draft must equal them), `POST drafts/{listingId}/publication` (exact `termsVersionId`), `POST recommendations`. Domain failures map to the existing safe codes (`FUNDING_NOT_VERIFIED`, `REVISION_CHANGED`, `FORBIDDEN`, …).

## Data and database enforcement

Migration `202610260007_work_simulated_reservations` adds one immutable `WorkSimulatedReservation` per slot (FK to the exact slot and terms version, SHA-256 of the exact reward vector, the legs). Migration `202610270001_work_reservation_binding` adds the exact returned funding reference, verifies the canonical vector digest and uses deferred guards to bind that record to the slot/version and terms reward vector. Canonical publication and replacement record the replaceable host callback's reference; the factory validates a bounded, unambiguous schema-valid catalog and returns coverage without writing the canonical record. This remains synthetic host-declared coverage, not a live balance, escrow or claim. The database validates binding, not the host's external financial truth. Existing built-in-adapter audit rows are reconciled only when their original reference, digest and vector match; missing or inconsistent historical evidence blocks migration without creating fictitious reservations. Preserve all reservation/slot/history rows on rollback; destructive downgrade is unsupported after use. Drafts are the T016 `WorkListing`/`TermsVersion` rows, so nothing new stores private scope.

## Verification

`tests/work-creation-form.test.ts` (typed terms, field problems, restore, reward review, teaser privacy), `-http`, `-host`, `-ui` (first paint, client) unit tests and the real-PostgreSQL `tests/work-creation-db.test.ts` (own authorized drafts, AC28 one-of-two assets, immutable vector-bound reservation) are mutation-checked. Playwright `playwright.work-creation.config.ts` (synthetic PostgreSQL, desktop and mobile, development and production servers) covers the full flow with publish, the two-asset block, retry with the same key, reload recovery, named validation problems and private/foreign/signed-out access. Limitations: no independent review beyond the risky-boundary note in the PR, no real wallet, provider or Guild authority, no UAT; flags stay off in deployed environments.

Entry point: the account menu lists **Create a Raid (guided)** only while `WORK_CREATION_READS_ENABLED` is exactly `true`.

Save responses read the receipt's exact listing/version, including versions outside the recent twenty. An old result retains its original revision/terms and carries `TERMS_VERSION_CHANGED` when newer terms exist; it cannot appear ready for publication. Missing/foreign publication targets both return FORBIDDEN. New publication requires DRAFT, or an already OPEN current available slot for safe concurrent duplicate intent; paused/terminal sources are not reopened.

The wizard receives the trusted account ID from its server page. Its account key remounts all in-memory state when that identity changes. Bounded schema-validated session storage holds incomplete form text, the confirmed listing binding and the exact pending save bytes/key before sending. A lost response is reconciled first, including across reload, before an edited intent can use the recovered listing/revision. Unknown successful-response contracts and server/transport uncertainty retain pending intent. A later expired-session or denied retry also preserves that earlier uncertainty until its exact receipt resolves; a retry rejection cannot prove the original never committed. Storage failure before transport prevents a new write. Successful publication clears that account's recovery; successful sign-out clears only this feature's recovery. Legacy unscoped text is discarded, never imported into a new account. Stale saved deadlines remain explicit and require the Founder to choose a new strictly increasing schedule; no replacement terms are silently invented.

Retained host boundaries: authenticated catalog visibility and server-authoritative coverage DTOs do not grant publication or financial authority. `publicTeaser` still has no public consumer: AC42 beyond the projection, real Guild authority, provider funds, UAT/business/release remain NOT VERIFIED.
