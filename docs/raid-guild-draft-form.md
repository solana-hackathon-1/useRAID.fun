## Owner pages and safe state

/creator/guild-drafts/new and /creator/guild-drafts/{uuid} use current server cookie/account context; edit loads only an authorized own strict DTO through storage. Missing/foreign/unavailable reads use the same fixed private-safe message. Anonymous pages show Sign in without serializing draft fields. Dynamic page metadata contains a generic title. Account links to creation; the saved record has a stable own edit URL. Root GUILD_DRAFTS_ENABLED remains defaultoff/non-demo; unavailable saving is explicit, owned saved details stay readable.

GuildDraftForm is a framework-free React19 component, injected GuildDraftTransport and GuildDraftFormState v1. It owns name/slug/description, one in-flight command, busy/status/error focus and local draft state. HTTP response/form schemas are exported from pure http-contracts.ts; the client imports no server receipt, cookies, Prisma or Next code. The host supplies React/JSX, styles for the orientation utility classes (or equivalent), strict authenticated state, a save/read transport and optional draftLinkPrefix. Root uses the same-origin private HTTP interface; alternate hosts inject their own transport and URL prefix.

Creation uses revision0/nullID; edit uses the current own UUID/revision and disables changing the saved slug. The server validates and remains the authority regardless of UI state. Strict response validation binds the saved result to the submitted fields/revision/target. A successful save shows its saved revision and fields plus Open saved draft; no public/verified badge is fabricated. React escapes user text; description is never rendered as HTML or fetched as a URL.

## Unknown acknowledgement and conflict

An unknown save freezes fields and retains the same key/full normalized body. Retry sends exactly that identity; an intervening401/403/429 after uncertainty preserves it rather than issuing a new create. Feedback says “Keep this page open” and retry with the same draft. A confirmed validation/slug denial permits correcting fields; an idempotency mismatch stays unresolved instead of blindly creating a new record. No browser storage or across-refresh unknown-command recovery is promised. A lost session/page requires a separate durable reconciliation contract before that guarantee can be made.

Known revision conflict preserves local fields and disables another save until Reload saved revision. Reload fetches the latest authorized state and shows its actual saved fields for comparison, retains local edits and asks the owner to review before saving. It neither discards the local draft nor silently overwrites a newer version. Error focus occurs after committed message rendering; fieldsets/buttons reflect busy/uncertain/disabled state, labels and status/alert roles support keyboard and mobile.
