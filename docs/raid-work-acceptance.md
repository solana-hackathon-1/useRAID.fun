# Accepting a Raid at the shared Root: consent and verified skills

A person can now record explicit consent to the exact terms of a slot and then accept it (directly for an instant-start Raid, or through the Founder's offer for an application Raid). The Root acceptance host approves only with that consent **and** a current verified skill assessment that meets every required skill. Simulated funds, default-off flags, API only: the browser screens that show the exact terms and the consent control are separate work.

Requirement mapping: T021 (Root acceptance part), T014/T013 dependencies read as designed, AG03/M2, blueprint §§08.5, 10.2, 12.1, 13, 16 (no money moves), 24.6–24.7, 28. Limits and gaps: O09 numeric promotion/score thresholds are OPEN and not used; the host requires **verified** evidence for every required skill (no claim-only starter path) and treats the terms' `assessmentPolicyVersion` as the assessment's policy version id, so terms using a placeholder policy cannot be satisfied; beneficiary is `simulated-beneficiary:` until payout destinations exist; Guild authority is the synthetic operator allowlist; Party, AI and influencer participants are not supported; the brief does not yet expose `termsDigest`, and no browser control calls these routes. Recording consent applies the acceptance gates it can know in advance: it is refused once the commitment deadline has passed (`DEADLINE_PASSED`) and, for an `APPLICATION` Raid, unless the person holds their own pending, unexpired offer for the exact slot and terms (`ADMISSION_REQUIRED`), so consent no longer probes slots the person cannot take. Full numbered task criteria, UAT and business/release approval remain NOT VERIFIED.

## Host contract

`WORK_ACCEPTANCE_ENABLED` (exact `true`, default off, plus workspace reads) and `WORK_ACCEPTANCE_TAXONOMY_ID` (the one published taxonomy the terms' skill ids belong to) must both be set; otherwise consent and acceptance are `WRITES_DISABLED`. Migration `202610270006_work_acceptance_consent` adds the table, an insert guard (available slot, open listing, current terms, stored digest) and an immutability trigger; destructive down migration is unsupported once used.
