# Stable skill taxonomy and private unverified claims

T012A implements reversible preparation contracts for08.1–2/07/09/11/23, R04–R06/R12/R15/R16, P07 and I06/I07/I10/I13. A claimed level is separate from an assessed rank. Wallet/token wealth, an alias, portfolio link or a claim of S never creates a verified rank, work eligibility, permission or extra capacity. Current T002/T006 assurance and future real assessment/persistence remain NOT VERIFIED.

## Public module and host contract

`src/skills/index.ts` exports `prepareSkillTaxonomyUpdate(previous, input)`, `resolveSkillAlias(publishedCatalog, alias)` and `prepareSkillClaim(context, input)` plus strict typed schemas/error codes from `contracts.ts`. Dependencies are zod4 and canonical identity/participant/entity/asset/state contracts (including bs58); runtime uses standard URL/Date. No Next/Prisma/auth/database singleton, environment, provider, fetch, secret key or logging is imported. The host owns current authentication/canonical HUMAN participant, restriction, trusted clock, actual published admin catalog and all future transaction/publication/assessment authority.

`PublishedSkillTaxonomySchema` requires a v1 catalog ID/revision, PUBLISHED state, publishing account/time and categories. A category has an opaque stable skill ID, immutable semantic domain, display name, ACTIVE/RETIRED status and normalized aliases. Aliases trim/lowercase, use ASCII letters/digits/dot/underscore/hyphen and are globally unique across the catalog; IDs are exact opaque identifiers. Technical bounds are1000categories,100aliases/category,100alias characters and200display/claim characters. These do not publish real categories or adopt a trial/assessment rubric.

`prepareSkillTaxonomyUpdate` accepts the actual previous published record or null for explicit bootstrap, and strict `{taxonomyId, expectedRevision, skills}`. Current ID/revision must match; first revision requires0 and produces1. Exact representable revision increments are enforced. Every previous ID, semantic domain and alias must survive; names and retirement can change, new categories/aliases can be added. Duplicate normalized aliases/IDs reject before ambiguous lookup. Result is frozen TAXONOMY_UPDATE_PROPOSAL with persisted/publishesTaxonomy/createsPermissionGrant false and a prospective catalog. It contains no publication authority. An actual admin command must independently authorize, compare-and-set under its transaction, audit and preserve immutable old versions before publication. That command/store does not exist in this slice.

`resolveSkillAlias` consumes a strict actual published catalog and normalized alias. It returns active canonical skill ID/domain/name and taxonomy reference; retired/unknown entries are SKILL_UNAVAILABLE. Renaming a category never reassigns frontend identity to Solana or removes an old alias. Existing work requirements continue to use shared stable skillId/minimumRank/assessmentPolicyVersion, with actual verified records checked at their command boundary; this resolver does not satisfy a requirement by itself.

`prepareSkillClaim` consumes strict current-self server context `{version, now, actorAccountId, actorSessionAuthorized, actorRestricted, participant, taxonomy}`. Only the canonical HUMAN participant account may prepare this M1 claim; other participant kinds are RESOURCE_UNAVAILABLE until their separate operator path exists. Missing/foreign/restricted sessions deny. Future-published or malformed catalogs/timestamp precision reject; current category must be active. Caller input is only `{skillId, claimedLevel, supportingReferences}`; participant/wallet/wealth/verified/rank/role fields are forbidden. References are0–5unique normalized HTTPS URLs, each at most2048characters without credentials, stored only in the private candidate and never fetched or endorsed as evidence.

Claim result is frozen versionv1/stateCLAIMED, tied to canonical participant, exact skill/domain and catalog reference, with preparation time, trimmed claimed level and supporting references. Assessed rank, rubric, evaluator, confidence, issue/reassessment dates remain null; sample size0 and empty assessment history report no assessment. informational=true and isAuthorizationToken/persisted/verifiesSkill/createsPermissionGrant/consumesCapacity=false. This is preparation, not an immutable stored claim or public profile projection. It does not erase prior assessments/history when a category retires; actual reassessment/revocation persistence remains future work.

## Errors, consumption and lifecycle

`SkillClaimContractError` sanitizes INVALID_INPUT, INVALID_HOST_CONTRACT, REVISION_CHANGED, HISTORY_CONFLICT, SKILL_UNAVAILABLE, AUTHENTICATION_REQUIRED, ACCOUNT_RESTRICTED, FORBIDDEN and RESOURCE_UNAVAILABLE without echoing private records or evidence. Host routes must authenticate before private lookup, enforce origin/rate/body limits, recheck current session/participant/catalog under actual save locks and map errors privately. No HTTP route, flag, DDL/backfill, save receipt, outbox, actual catalog administration, evaluator or rank assignment is added here.

[The independent Node22.12+ consuming host](../examples/skill-claims/README.md) dereferences canonical links, installs its own exact zod4.6.5/bs586.0.0/tsx4.23.15 and exercises alias/domain identity, canonical participant, renamed catalog candidates, forbidden history reassignment and unverified claims despite wealth fields. Synthetic published-admin facts never establish real approval. Replacing a catalog/auth/storage host preserves canonical IDs/domains/old aliases and accepted record references; do not silently migrate an old requirement or assessment to another skill/rubric.

Future storage must retain immutable claim/evidence/assessment versions, trusted evaluator/rubric/verification provenance, confidence/sample denominators and reassessment/revocation history; external token expiry cannot silently revoke a documented assessment. Actual assessment/UAT cannot be inferred from a candidate or mock. Rollback removes the unused preparer while preserving existing identity/preferences/work/claims; no migration cleanup occurs.
